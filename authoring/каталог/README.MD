# Каталог действий по документам

Здесь лежат feature-файлы **другого жанра**, чем в `../features/`.

| | `../features/` | `каталог/` |
|---|---|---|
| Что это | рабочая операция агента | справочник возможных действий |
| Порядок шагов | сквозной, от начала до конца | никакого, каждый блок сам по себе |
| Контракт результата | обязателен | отсутствует |
| Запускается | да, целиком | **нет** |
| Один файл — это | одна операция | один документ |

Рабочий сценарий отвечает на вопрос «как сделать вот это». Каталог отвечает
на вопрос «а что вообще можно сделать с этим документом».

## Зачем

У модели нет карты интерфейса 1С. Попросите «оформи отпуск с компенсацией» —
и без каталога она пойдёт искать поле «компенсация» наугад. Каталог
превращает поиск в выбор: нужное действие уже описано готовым блоком с
настоящими именами элементов, остаётся скопировать его и обернуть в контракт.

## Что уже есть

Здесь остались словари документов, под которые **пока нет операции агента**:

| Файл | Документ | Действий | Откуда имена | `check_syntax` |
|---|---|---|---|---|
| `ОперацияУчетаНДФЛ.feature` | `Документ.ОперацияНалоговогоУчетаПоНДФЛ` | 21 | живая форма | ✅ |
| `ОперацияУчетаВзносов.feature` | `Документ.ОперацияУчетаПоСтраховымВзносам` | 17 | живая форма | ✅ |
| `Отпуск.feature` | `Документ.Отпуск` | 31 | живая форма | ✅ |

**Словари действующих операций переехали к своим скиллам** — там они не
справочник на будущее, а рабочий инструмент модели:

| Скилл | Словари |
|---|---|
| `.claude/skills/zup-payroll-accrual/` | `СловарьДействий.feature` — начисление зарплаты и взносов |
| `.claude/skills/zup-advance-accrual/` | `СловарьДействий.feature` — начисление за первую половину месяца |
| `.claude/skills/zup-payout/` | четыре ведомости: в кассу, в банк, на счета, через раздатчика |

Правило простое: появилась операция — словарь уходит в скилл; словарь без
операции живёт здесь.

Первые три проходят `check_syntax` без ошибок. Это не формальность: проверка
подтверждает, что **каждый шаг существует в библиотеке Vanessa**, а не
придуман. Имена элементов сняты с живых форм клиента тестирования
24.08.2026, ЗУП КОРП 3.1.30.178 — не из исходников конфигурации, поэтому
учтена фактическая видимость полей.

**Два файла начислений собраны иначе** — по `Ext/Form.xml` из исходников
`исходники-конфигурации`, порядок описан в `../Memory.MD`. Разница
принципиальная, и её надо держать в голове:

- имена элементов настоящие, но **видимость не учтена**: статический разбор
  не знает, что скрыто при текущих настройках учёта;
- команды, которые платформа создаёт в рантайме, в `Form.xml` отсутствуют —
  такие блоки помечены комментарием `# автокоманда`, имя предсказано
  по шаблону и подтверждения не имеет;
- ~~группа `ВыплатаГруппа` в документе начисления зарплаты в исходниках пуста~~
  — **снято с живой формы 25.08.2026.** Внутри оказались `ПорядокВыплаты`
  и `ПланируемаяДатаВыплаты`. Второе поле важнее, чем кажется: 1С требует,
  чтобы планируемая дата выплаты была не раньше даты документа, и именно
  на этом не проходило проведение январского начисления, сделанного в
  августе. Блок для обоих полей теперь в каталоге есть;
- `check_syntax` на них не запускался: у сессии, которая их писала,
  не было доступа к MCP.

Первый же перенос блока в рабочий сценарий это проверит.

## Как пользоваться

1. Найдите нужное действие по заголовку `Сценарий:`.
2. Скопируйте его шаги в файл в `../features/`.
3. Этап, после падения которого продолжать бессмысленно, оберните
   в `Попытка / Исключение` с остановкой фичи — см.
   `../../docs/02-архитектура.md`.
4. Переменные уже названы по правилам проекта: `$$ПеременнаяЧтоТо$$`.

## Соглашения

- Тег `@НеЗапускать` на каждом файле. Он ничего не делает технически —
  это метка для человека и для агента.
- Комментарии `#` внутри сценариев несут то, чего не видно по именам:
  скрытые группы, расхождение заголовка и имени элемента, устаревшие
  закладки.
- Переменные — только кириллица. Латинская `o` в `Количествo` выглядит
  идентично, а подстановка `$$...$$` молча не срабатывает. Одну такую уже
  поймали.

## Что стоит знать про эти документы

**Операция учета НДФЛ.** Семь таблиц: доходы, исчисленный налог по 13%,
предоставленные вычеты, взносы как соц.вычеты, удержанный налог,
переданный в налоговый орган, перечисленный. Последняя устарела — на форме
прямо написано, что с 1 января 2024 года эти данные в учёте не отражаются.
Поле «Сотрудник» называется `ФизическоеЛицо`.

**Операция учета взносов.** Период задаётся **строкой месяца**
(«Август 2026»), а не датой. Из полей взносов видны только две суммы —
до превышения предельной величины и сверх неё; поля ПФР страховая,
накопительная, ФФОМС и ФСС скрыты, они остались от тарифов до 2023 года.
Таблицы пособий по соц. страхованию и по уходу за ребёнком **скрыты по
умолчанию** — блоки для них в каталоге есть, но сработают только после
того, как группы будут показаны.

**Отпуск.** Список называется «Отпуска (Т-6)». У таблицы `Начисления`
**нет кнопок Добавить и Удалить** — строки создаёт только кнопка
«Рассчитать», вручную их не завести, можно лишь править через «Изменить».
Флаг «Расчет утвердил» (`ДокументРассчитан`) кнопка «Рассчитать» не ставит.

**Начисление зарплаты и взносов.** Объект называется `НачислениеЗарплаты`,
без слова «Взносов» — легко ошибиться. Одиннадцать таблиц: начисления,
договоры ГПХ, пособия, управленческие начисления, льготы, удержания, НДФЛ,
займы, взносы, корректировки выплаты и отдельная закладка доначислений с
четырьмя таблицами-двойниками (суффикс `Перерасчет`). Заполнение — три
разные кнопки: `Заполнить`, `ЗаполнитьССохранениемИсправлений` и
`Дозаполнить`. Кнопки `ДоначислитьСейчас` и `ПересчитатьСотрудников` живут
в группе, которая появляется только вместе с надписью «Требуется
доначисление или перерасчет зарплаты» — пока перерасчёт не нужен, их
на форме нет.

**Начисление за первую половину месяца.** Это отдельный документ, а не режим
документа зарплаты: таблиц четыре вместо одиннадцати, итогов два вместо
четырёх, взносы здесь не считаются. Граница «первой половины» — поле
`ПериодНачисленияДатаОкончания` с заголовком «Расчет первой половины месяца
до». Флаг `ИсчислятьНалогПриОкончательномРасчете` решает, появятся ли вообще
строки на закладке НДФЛ. Две ловушки в именах: колонка физлица в удержаниях
называется `УдержанияФизЛицо`, а в документе зарплаты — `УдержанияФизическоеЛицо`;
кнопка подбора называется `НачисленияПодборСотрудников`, а в документе
зарплаты — `ПодборСотрудников`. Ещё у таблицы начислений есть вторая
командная панель `КомандыНачисления`, где кнопки названы коротко и без
префикса таблицы: `Добавить`, `Изменить`, `Удалить`.

**Четыре ведомости на выплату.** Руководство (глава 16) описывает четыре
места выплаты, а не три: банк по зарплатному проекту, произвольные счета,
касса и раздатчик. Формы почти одинаковые, различается один реквизит шапки:
`ЗарплатныйПроект`, `Банк`, `Касса` или `Раздатчик`.

Ловушка в именах: кнопка правки суммы у раздатчика называется
`Редактировать`, а у остальных трёх — `РедактироватьЗарплату`. Кнопка
правки налога везде одна и та же, `РедактироватьНДФЛ`.

Общее и важное:

- **У таблицы `Состав` нет кнопки «Добавить».** Ни в одной из трёх. Пустую
  строку завести нельзя: строки создаёт либо `Заполнить`, либо `Подобрать`.
  Из стандартных команд у таблицы остались только `СоставУдалить` и
  `СоставЗакончитьРедактирование`.
- **Суммы правятся не прямо в колонке.** Сначала жмётся кнопка-переключатель
  `РедактироватьЗарплату` («Изменить зарплату») или `РедактироватьНДФЛ`
  («Изменить налог»), и только потом колонка принимает ввод. Вернуть
  расчётные значения — `ОбновитьНДФЛ`.
- **Половина «интересных» элементов на новом документе скрыта**, и это видно
  только на живой форме: `ДатаВыплаты`, флаг `ПеречислениеНДФЛВыполнено`,
  депонирование и сведения о незачисленной зарплате, `Подразделение`,
  `Округление`, `ПроцентВыплаты`, `НомерРеестра`, `ВидЗачисления`, подписи.
  Такие блоки в каталоге помечены комментарием — безусловно в рабочий
  сценарий их ставить нельзя.
- Различия в составе колонок: у банковской ведомости целая группа способов
  зачисления (лицевой счёт, карта, СНИЛС, телефон, счёт), у ведомости на
  счета — одна колонка `СоставБанковскийСчет`, у кассовой — ничего из этого.
  Колонка «Взыскано» есть у банковской и на счета, у кассовой её нет.

Заголовок поля `ПериодРегистрации` во всех трёх — «Месяц выплаты», а реквизит
за ним — `ПериодРегистрацииСтрокой`: это месяц строкой, а не дата.

## Чего в каталоге нет

Действия описаны, но **ни одно не прогонялось**. Каталог собран из разбора
форм, а не из выполнения. Первый же перенос блока в рабочий сценарий это
проверит — и, если что-то не сойдётся, правку надо вернуть сюда.
