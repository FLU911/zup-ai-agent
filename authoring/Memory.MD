## Баги MCP на этой версии (1.2.043.28)

### `get_VanessaAutomation_state` → `isCodeEditor`

```
Internal error: Значение не является значением объектного типа (isCodeEditor)
```

Пока в редакторе Vanessa ни разу не открывали feature-файл. Лечится вызовом
`open_feature_file`. После этого инструмент отвечает нормально.

Последствие для протокола: Исследователь не сможет выполнить Шаг 1a
(проверка состояния записи действий) на «холодной» Vanessa. Сначала откройте
любой feature-файл.

### `check_syntax` → `ЗаписатьЛогВЖРИнформацияСервер`

```
Internal error: Ошибка при вызове метода контекста (ЗаписатьЛогВЖРИнформацияСервер)
```

Та же природа. `check_syntax` с полным путём к файлу, который ещё не
открывали в редакторе, падает. Всегда `open_feature_file` перед `check_syntax`,
даже если путь передаётся явно.

## Особенности ЗУП, найденные при написании сценариев

### Регламентированные отчёты

- Форма списка — `Документ.РегламентированныйОтчет`, окно
  «Регламентированная отчётность».
- Форма конкретного отчёта открывается как основная форма отчёта, например
  `Отчет.РегламентированныйОтчет6_НДФЛ`, окно «6-НДФЛ (с 2021 года)».
- Период переключается кнопками `УстановитьПредыдущийПериод` /
  `УстановитьСледующийПериод`, текущее значение читается из
  `ПолеВыбораПериодичностиПоказаПериода`. Прямой установки нет: поле
  `ТолькоПросмотр=Да`, форма выбора недоступна (`open_choice_form` →
  «Неподходящее состояние элемента управления»).
- **Форма открывается на периоде, который соответствует текущей дате сеанса,
  а не на начале года.** Прогон 24.08.2026 открыл форму сразу на
  «1 полугодие 2026 г.». Любая логика вида «нажать N раз от 1 квартала»
  ломается в другой день. Рабочий паттерн — два цикла с выходом по совпадению:

  ```gherkin
  И я делаю 12 раз
  	Если элемент формы с именем 'ПолеВыбораПериодичностиПоказаПериода' имеет значение "$$ПеременнаяПериод$$" тогда
  		Тогда я прерываю цикл
  	И я нажимаю на кнопку с именем 'УстановитьПредыдущийПериод'
  И я делаю 24 раз
  	Если элемент формы с именем 'ПолеВыбораПериодичностиПоказаПериода' имеет значение "$$ПеременнаяПериод$$" тогда
  		Тогда я прерываю цикл
  	И я нажимаю на кнопку с именем 'УстановитьСледующийПериод'
  Тогда элемент формы с именем 'ПолеВыбораПериодичностиПоказаПериода' стал равен "$$ПеременнаяПериод$$"
  ```

  Сначала идём назад (цель может быть в прошлом), потом вперёд (цель может
  быть в будущем). Оба цикла ограничены, финальная проверка ловит промах.
- Дата подписи правится в табличном документе: переход к именованной ячейке
  `ДатаПодписи`, двойной клик, ввод текста.
- Заполнение открывает `ОбщаяФорма.ДлительнаяОперация`. Ждать до 1800 секунд.
- Кнопка «Проверить» (контрольные соотношения) даёт предупреждение
  «При проверке контрольных соотношений ошибки не обнаружены».
- Кнопка `ПроверитьВыгрузку` даёт предупреждение «Ошибок не обнаружено».
- Выгрузка файла: сначала `я выбираю файл '<каталог>'`, затем кнопка `Выгрузить`.
  Признак успеха — строка в логе TestClient по шаблону
  «Файл выгрузки регламентированного отчета * сохранен в каталог *».
- **Каталог выгрузки обязан заканчиваться разделителем.** Направление слэша
  не важно, важен сам разделитель в конце — проверено все четыре комбинации:

  | Значение `ПеременнаяПутьКФайлу` | Результат |
  |---|---|
  | `<каталог>` | ❌ |
  | `<каталог>\` | ✅ |
  | `<каталог>` | ❌ |
  | `<каталог>/` | ✅ |

  1С склеивает каталог с именем файла без разделителя, поэтому без слэша
  путь превращается в `<каталог>СФР_….xml` — это запись в корень диска, куда
  нет прав. В сообщениях пользователю выглядит как «Не удалось записать
  файл … возможно, нет прав для записи в выбранный каталог», что уводит
  в сторону прав доступа.
- Форма отчёта — **версионная**: у ЕФС-1 ОСС за 1 полугодие 2026 это
  `Отчет.РегламентированныйОтчетЕФС1ОСС.Форма.ФормаОтчета2026Кв2`. Имя формы
  меняется вместе с редакцией бланка, привязываться к нему нельзя.
  Кнопка с заголовком «Записать» имеет имя `Сохранить`.
- Между «Заполнить» и «Сохранить» может вклиниться промо-окно
  «Сдавайте отчетность прямо из программы»
  (`Обработка.ОбщиеОбъектыРеглОтчетности.Форма.ПредложениеОформитьЗаявлениеНаПодключение`).
  Оно забирает фокус, и клик по кнопке отчёта падает. После его закрытия
  **активного окна не остаётся** — окно отчёта нужно активизировать явно:

  ```gherkin
  Если появилось окно с заголовком "Сдавайте отчетность прямо из программы" Тогда
  	И я закрываю окно "Сдавайте отчетность прямо из программы"
  	И я активизирую окно "ЕФС-1*"
  ```

  **Почему оно появляется не каждый раз.** Форма сама себя throttl-ит,
  логика в `Ext/Form/Module.bsl` этой формы:

  ```bsl
  БольшеНеПоказывать = ХранилищеОбщихНастроек.Загрузить(
  	"Обработка.ОбщиеОбъектыРеглОтчетности",
  	"НеПоказыватьПредложениеОформитьЗаявлениеНаПодключение");
  Если БольшеНеПоказывать = Истина Тогда
  	Отказ = Истина;
  КонецЕсли;
  ВремяПоследнегоНапоминания = ХранилищеОбщихНастроек.Загрузить(
  	"Обработка.ОбщиеОбъектыРеглОтчетности", "ВремяПоследнегоНапоминания");
  Если ВремяПоследнегоНапоминания <> Неопределено
  	И ВремяПоследнегоНапоминания + 4 * 60 * 60 > ТекущаяДатаСеанса() Тогда
  	Отказ = Истина;
  КонецЕсли;
  ```

  То есть после первого показа окно молчит **4 часа**. Это худший вид
  нестабильности: сценарий зелёный весь день и падает утром следующего.
  Гасится наглухо записью в хранилище общих настроек — один раз на базу,
  под тем пользователем, под которым работает клиент тестирования:

  ```gherkin
  И я выполняю код встроенного языка на сервере через буфер обмена (Расширение)
  """bsl
  	ХранилищеОбщихНастроек.Сохранить(
  		"Обработка.ОбщиеОбъектыРеглОтчетности",
  		"НеПоказыватьПредложениеОформитьЗаявлениеНаПодключение",
  		Истина);
  """
  ```

  Держим оба уровня: настройку — чтобы окна не было, условие в сценарии —
  на случай чужой базы, где настройку никто не ставил.
- **Каждый прогон создаёт новый документ регламентированного отчёта.**
  Кнопка `ОткрытьФормуОтчета` (заголовок «Создать») всегда делает новый
  экземпляр, существующий отчёт за тот же период она не переоткрывает.
  После семи прогонов в базе семь ЕФС-1 за 1 полугодие 2026 по «Крон-Ц».
  Для боевой операции агента это надо решать отдельно.

### Физические лица и сотрудники

Проверено прогоном 24.08.2026, сценарии `12` и `13`.

- **ФИО вводится одним полем `ФИО`.** Поля `Фамилия`, `Имя`, `Отчество` на
  форме `Справочник.ФизическиеЛица.Форма.ФормаЭлемента` есть, но
  `Видимость:Нет` — 1С разбирает строку сама.
- **Кнопка записи — `КомандаЗаписатьИЗакрыть`.** Рядом лежит
  `ФормаЗаписатьИЗакрыть` с тем же заголовком и `Видимость:Нет`. По
  исходникам их не различить, ошибиться легко.
- **Место рождения — не поле, а отдельная форма.** Прямой ввод и выбор из
  списка дают ошибку «Неподходящий тип элемента управления». Открывается
  кнопкой выбора, внутри `ОбщаяФорма.ВводМестаРождения` с полями `Город`,
  `Район`, `Область`, `Страна` и кнопкой `ОК`.
  Паспортное `ПОС. ЛУГОВОЙ ТЮМЕНСКОЙ ОБЛ.` приходится раскладывать по полям.
- **`ДокументыФизическихЛицСтранаВыдачи` — обязательное скрытое поле.**
  При анализе формы оно `Видимость:Нет`, но при записи 1С отказывает:
  «Не указана страна выдачи документа». Заполнять после выбора вида документа.
- **ИНН и СНИЛС проверяются по контрольным разрядам прямо в поле.**
  Произвольные цифры не пройдут. Для тестовых данных считайте КС честно —
  генератор в `authoring/scans/generate_scans.py`.
- **Сотрудник создаётся в `Обработка.СписокСотрудников.Форма.ФормаСпискаСотрудников`**,
  кнопка `Создать` (не `СписокСоздать`, та невидима). Нужны только
  `ГоловнаяОрганизация` и `ФИО` — остальное подтянется из физлица.
- **При записи сотрудника с существующим физлицом 1С показывает модальный
  диалог «Найден похожий человек»** с кнопками `ДаЭтоТотКтоМнеНужен` и
  `НетЭтоДругойЧеловек`. Это встроенная защита от дублей физлиц —
  отвечать `Да` обязательно, иначе получите второе физлицо на того же
  человека. Модальное окно ломает шаг клика, разбор — в `docs/04`.
- **`get_table_data` с `name_filter` ищет по точному совпадению**, не по
  подстроке: `Астахова` не найдёт «Астахова Мария Игоревна».

### Список документов «Отпуск»

- Окно называется «Отпуска (Т-6)».
- Полезный отбор для пачечной обработки: «Дата начала события», «Организация»,
  «Документ рассчитан», «Пометка удаления», «Проведен».
- После расчёта нужно **вручную установить флаг** `ДокументРассчитан` —
  кнопка «Рассчитать» его не ставит.

### Регламентированный отчёт не открывается напрямую

Шаг `Я открываю основную форму отчета "РегламентированныйОтчетЕФС1ОСС"`
на «холодном» клиенте **зависает**: форма не открывается, шаг не возвращает
управление. Проверено через `execute_feature_step`, два прогона.

Рабочий сценарий 6-НДФЛ делает иначе — сначала открывает список
регламентированной отчётности:

```gherkin
Когда Я открываю основную форму списка документа "РегламентированныйОтчет"
Тогда открылось окно "Регламентированная отчетность"
...
Когда Я открываю основную форму отчета "РегламентированныйОтчет6_НДФЛ"
```

Вывод: для регламентированных отчётов сначала открываем рабочее место,
потом форму отчёта. Черновик ЕФС-1 в `drafts/` этого не делал — в
`authoring/features/11_ОтчетностьЕФС1.feature` порядок исправлен.

### `load_features` не принимает каталог

Описание инструмента говорит «путь к каталогу или файлу», но на каталог
он отвечает ошибкой:

```
Internal error: Ожидался путь к .feature файлу, а не к каталогу
```

Загружайте файлы по одному через `open_feature_file` или `load_features`
с путём к конкретному `.feature`.

### Шаг «я закрываю все окна клиентского приложения» может зависнуть

Если открыто окно `Информация` (`Обработка.ИнформацияПриЗапуске`) или
`Монитор Портала 1С:ИТС`, шаг не завершается. Помогает точечное закрытие:

```
mcp__VA__window_management(action="close", window_title="Информация")
mcp__VA__window_management(action="close", window_title="Монитор Портала 1С:ИТС")
```

## Где брать имена элементов формы

Исходники конфигурации лежат в `исходники-конфигурации`. Имена элементов —
в `Ext/Form.xml` каждой формы:

```
Documents\<ИмяДокумента>\Forms\ФормаДокумента\Ext\Form.xml
Reports\<ИмяОтчета>\Forms\<ИмяФормы>\Ext\Form.xml
```

Внутри — элементы вида `<InputField name="Организация" id="123">`,
`<Button name="ФормаПровестиИЗакрыть" ...>`, `<Table name="Начисления" ...>`.
Синоним объекта (основа заголовка окна) — в `<Synonym>` файла `<ИмяОбъекта>.xml`.

Это быстрее и надёжнее, чем угадывать. Но статический разбор не покажет
видимость элемента в конкретный момент и фактический заголовок окна —
это только прогоном.

Обратите внимание: документ «Начисление зарплаты и взносов» называется

они открываются на автогенерируемой форме СКД.
