# Указатель веб-словарей: какой файл под какую задачу

Словарь — проверенный вызовами путь по формам ЗУП в веб-клиенте: какие
инструменты вызвать, с какими аргументами, что проверить и где ловушки.
**Открывать ДО первого действия в 1С.** Один словарь дешевле трёх промахов.

| Задача | Словарь |
|---|---|
| **Любая работа в веб-клиенте — первым** | `ОбщиеПриемы` |
| Документа нет, «Создать» недоступна, нужного вида нет в выборе | `НастройкиФункциональныеОпции` |
| Сколько сотрудников работает на дату, кто именно | `СоставСотрудниковНаДату` |
| Материальная помощь, в том числе при рождении ребёнка | `МатериальнаяПомощь` |
| Приз, подарок сотруднику | `ПризПодарок` |
| Закрыть месяц: начисление зарплаты, ведомости, выплата межрасчётных | `НачислениеЗарплатыИВыплата` |
| Итоги месяца: начислено, НДФЛ, к выплате, выплачено | `ОтчетыПроверкиМесяца` |
| 6-НДФЛ, ЕФС-1, контрольные соотношения, проверка выгрузки | `6НДФЛиЕФС1` |

Словаря под задачу нет — работать по `ОбщиеПриемы` и сказать человеку,
какого словаря не хватило. Предметная часть (коды, учёт, разбор КС) для
остальных документов — в первой версии, `list_dictionaries` без `ZUP_DICT=web`.

## Три правила, которые экономят больше всего

1. **Форму и отчёт открывать ссылкой** из словаря через `open_list`,
   а не искать по разделам.
2. **После ввода — перечитать.** Даты, виды расчёта, период по умолчанию
   почти всегда не те, что в задании, и документ с ними проводится молча.
3. **Не выдумывать реквизиты.** Не хватает ОКТМО, регномера, счёта —
   это ответ человеку, а не повод вписать правдоподобное число.
