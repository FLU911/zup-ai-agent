# Начисление зарплаты и выплата — закрытие месяца

> `<В УГЛОВЫХ СКОБКАХ>` — подставить из задания или прочитать с формы.
> Других значений в этом файле нет: всё, что без скобок, — имена кнопок,
> полей и документов 1С.

**Что решает:** «закрой месяц»: начисление зарплаты и ведомости по каждой
организации, выплата межрасчётных документов.

Путь проверен вживую 15.09.2026 на одной организации (ведомость
на счета) и на выплате межрасчётного документа (ведомость в банк).
Организации с ведомостью в банк на десятки человек и с кассой в вебе
не проходились — путь тот же, вид ведомости обработка выбирает сама.

## Порядок месяца в этой базе

1. Межрасчётные документы месяца (матпомощь, подарки, увольнения) —
   ДО начисления зарплаты. Их создаёт задание или человек.
2. По каждой организации: «Начисление зарплаты и взносов» → «Выплатить».
3. Межрасчётные с «В межрасчетный период» — своя выплата кнопкой
   «Выплатить» на самом документе.
4. Проверка отчётом — `ОтчетыПроверкиМесяца`.

**Аванса в этой базе нет** — ни одного «Начисления за первую половину
месяца» за всю историю расчётов. Не начинать с аванса: 15.09.2026 модель
так и сделала и провела пустые ведомости.

«Отражение в бухучёте» задание «закрой месяц» здесь не включает — в истории
базы месяцы закрыты двумя видами документов.

## Начисление зарплаты (одна организация)

    open_list(metadata_path="Документ.НачислениеЗарплаты")
    click(text="Создать")                                  # подменю из четырёх пунктов
    click(text="Начисление зарплаты и взносов")
    select_value(field="Организация", search="<ОРГАНИЗАЦИЯ>")   # СНАЧАЛА организация
    get_form_state()
        # МесяцНачисленияСтрокой — месяц задания? Дата — сегодня (НЕ то);
        # ПланируемаяДатаВыплаты — это и есть нужная дата документа
    fill_field(field="Дата", value="<значение ПланируемаяДатаВыплаты с формы>")
    click(text="Заполнить")                                # подменю с одним пунктом
    click(text="Заполнить")
    wait_seconds(seconds=5)                                # на большой организации дольше
    get_form_state()
        # ИтогНачислено, ИтогУдержано, ИтогВзносы не нули; таблица Начисления rowCount > 0
    click(text="Провести")
        # в заголовке появился номер документа и дата

## Выплата — кнопкой «Выплатить», а не новой ведомостью

Сразу на проведённом документе начисления:

    click(text="Выплатить")
        # форма «Выплата начисленной зарплаты»: По документу — наш документ;
        # Выплачивать «Начисление зарплаты»; Дата выплаты; таблица Ведомости
    get_table(table="Ведомости")
        # Тип — «Ведомость в банк» / «Ведомость на счета» / «Ведомость в кассу»;
        # Сумма = начислено − удержано; Сотрудники — все из начисления
    click(text="Провести и закрыть")
    close_form()                                            # закрыть документ начисления

Вид ведомости обработка берёт из места выплаты сотрудников — выбирать его
не нужно. У разных организаций вид разный, и это нормально.

## Межрасчётный документ (матпомощь, отпуск, увольнение)

    open_list(metadata_path="Документ.<ИМЯ ДОКУМЕНТА, например МатериальнаяПомощь>")
    click(text="<сотрудник в строке списка, как там написан>")   # выделить строку
    click(text="Выплатить")
        # Выплачивать — вид документа; Дата выплаты = планируемая дата из документа
    get_table(table="Ведомости")
    click(text="Провести и закрыть")

## Проверка

    open_list(metadata_path="Документ.ВедомостьНаВыплатуЗарплатыВБанк")
        # или ВедомостьНаВыплатуЗарплатыПеречислением, ВедомостьНаВыплатуЗарплатыВКассу
    filter_list(text="<ДАТА ведомости ДД.ММ.ГГГГ>")        # по дате; по «Месяц ГГГГ» не находит
    get_table()
        # Способ выплаты, Сумма, Сотрудники, _posted: true

Итоги по организации — отчётом, `ОтчетыПроверкиМесяца`.

## Ловушки

1. **Пустая ведомость проводится молча.** Ведомость, созданная кнопкой
   «Создать» в списке ведомостей и «Заполнить», в этой базе собирает
   одного-двух человек или никого. «Выплатить» на документе собирает
   весь долг по нему.
2. **Дата документа по умолчанию — сегодня.** Ставить
   `ПланируемаяДатаВыплаты`, прочитанную после выбора организации.
   Правило «последний день месяца» ломается на выходных.
3. **Организация сбрасывает месяц** на месяц рабочей даты — сначала
   организация, потом месяц (если месяц не текущий).
4. **«Создать» и «Заполнить» открывают подменю** — второй `click` по пункту.
5. Списки отсортированы от старых к новым — искать отбором по дате.
