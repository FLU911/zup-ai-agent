# Словари для веб-клиента — версия 2 (пилот)

Первая версия словарей (`drafts/словари/*.feature`) написана под руки
Vanessa Automation: шаги Gherkin, действия `manage_form_elements`,
`execute_form_actions`, `get_form_analysis`. Прогон GigaChat через
веб-клиент 15.09.2026 показал, что слабая модель такой словарь читает,
но не переводит в свои инструменты: в Я3 прочитала «СНАЧАЛА ВКЛЮЧИТЬ
ОПЦИЮ» со ссылкой на форму — и следующим шагом пошла в «Разовые
начисления».

Версия 2 пишется **сразу вызовами тех инструментов, которые видит
модель**. Ничего переводить не нужно: строку из словаря можно вызвать.

## Правило: в словаре нет данных базы

В путях только заполнители `<ОРГАНИЗАЦИЯ>`, `<ФИО>`, `<ФАМИЛИЯ>`, `<СУММА>`,
`<ДАТА>` — и одна строка вверху каждого файла, что в скобках подставляется
из задания. Без скобок остаются только имена 1С: кнопки, поля, виды расчёта,
коды дохода и вычета, варианты периодов.

Почему не «пример»: 15.09.2026 в первой редакции пилота пути были написаны
на настоящих данных проверки. Две беды сразу: слабая модель копирует значение
из вызова буквально, пометку «это пример» рядом она не читает; и данные
проверки совпадают с эталонами бенчмарка — модель получала бы готовый ответ.

Настоящие значения живут в `ПРОТОКОЛ-ПРОВЕРКИ.md`. Его, как и этот README,
сервер знаний модели не отдаёт.

## Формат

Markdown, а не `.feature`: словарь не исполняется, а Gherkin-обёртка
слабой модели ничего не даёт, кроме лишних токенов.

Каждый файл:

1. **Что решает** — одной фразой, какие задания закрывает.
2. **Путь** — нумерованные вызовы инструментов с аргументами, дословно.
   Что в ответе смотреть после вызова — сразу под ним.
3. **Проверка** — чем доказать результат по базе, а не по ответу кнопки.
4. **Ловушки** — только проверенные в вебе. Ловушки из первой версии,
   которые в вебе НЕ воспроизвелись, отмечены отдельно: это тоже знание.
5. **Первая версия** — ссылка на `.feature`, где лежит предметная часть
   (коды, суммы, объяснения учёта), которую сюда не копировали.

## Инструменты, которыми написаны пути

| Инструмент | Что делает | Функция web-test |
|---|---|---|
| `open_section(name)` | раздел левой панели, отдаёт команды раздела | `navigateSection` |
| `open_command(name)` | команда раздела по заголовку | `openCommand` |
| `open_list(metadata_path)` | список или форма по имени: `Документ.X` **или ссылка `e1cib/app/...`** | `navigateLink` |
| `get_form_state()` | поля (техническое имя + подпись + значение), кнопки, таблицы | `getFormState` |
| `click(text, double_click, table)` | кнопка, пункт подменю, вкладка, строка | `clickElement` |
| `fill_field(field, value)` | поле шапки, флажок, дата | `fillFields` |
| `select_value(field, search)` | ссылочное поле, выбор из списка | `selectValue` |
| `fill_table_row(fields_json, row_index, table)` | ячейки строки таблицы | `fillTableRow` |
| `get_table(table, max_rows, offset)` | строки списка или табличной части | `readTable` |
| `get_report(columns, offset, max_rows)` | сформированный отчёт страницами | `readSpreadsheet` |
| `get_screen_text(contains)` | текст окна, которое не форма (результат КС) | фреймы `tempstorage` |
| `filter_list(text, column)` | поиск в списке | `filterList` |
| `close_form(save)` | закрыть форму, а если формы нет — окно крестиком | `closeForm` |
| `press_keys(text, key)` | набор с клавиатуры в поле с фокусом | `page.keyboard` |
| `wait_seconds(seconds)` | подождать фоновое действие | `wait` |

Модель, у которой вместо этих инструментов голый web-test (Claude через
Bash), читает таблицу справа налево — аргументы те же.

## Как словари отдаются модели

Тот же сервер знаний, `C:\claude\сбер\knowledge_server.py`, с переменной
окружения `ZUP_DICT=web`: `list_dictionaries` и `get_dictionary` тогда
смотрят в эту папку. Без переменной — прежние словари для Vanessa.
