# Словари действий по операциям руководства ЗУП

154 словаря: документы, справочники и два плана видов расчёта —
начисления и удержания. Основная часть сгенерирована из исходников
конфигурации ЗУП КОРП 3.1 (папка `исходники-конфигурации`) инструментом
`../инструменты/сгенерировать-словарь.py`, остальные сняты с живых форм
по ходу работы.

## Три состояния словаря

| Тег в шапке | Что это значит |
|---|---|
| `@черновик` | имена из `Form.xml`, живой формой не подтверждены |
| `@проверено` | форма открыта, состав сверен, расхождения записаны в файл |
| нет тега | снят руками с живой формы при работе над операцией |

На 31.08.2026: форму видели 58 словарей из 154, остальные 96 —
черновики. Как проверять и что при этом находится —
`../../docs/09-покрытие-и-проверка-словарей.md`.

## Что это

По одному файлу на документ. Каждый файл — перечень того, что можно
сделать с объектом: закладки, поля шапки, флаги, переключатели, команды
формы, таблицы с колонками и их командами. Имена элементов настоящие,
взяты из `Documents\<Имя>\Forms\ФормаДокумента\Ext\Form.xml`.

На всех стоит `@каталог`, `@НеЗапускать`, `@черновик`.

## Чем это НЕ является

**Видимость и доступность элементов не проверены.** Form.xml знает
имена, но не знает, что покажет форма в конкретный момент: половина
элементов скрыта функциональными опциями, настройками учёта и
состоянием документа. Это выяснится только прогоном.

Именно поэтому стоит тег `@черновик`, а файлы лежат в `drafts/`, а не
в `.claude/skills/`. Черновик становится словарём после того, как
человек прогнал операцию на живой форме и вычистил лишнее.

Практический опыт этой сессии: на форме сотрудника поле номера лицевого
счёта присутствует в исходниках, но на живой форме **всегда невидимо и
недоступно** — правится только через регистр. Из Form.xml этого не
видно никак.

## Порядок доведения черновика до словаря

1. Прогнать операцию руками или через MCP, отмечая, что реально видно.
2. Выкинуть невидимое и неиспользуемое — файл должен быть коротким.
3. Сгруппировать по смыслу, а не по типу элемента: не «все поля шапки»,
   а «Заполнить шапку», «Указать сроки», «Настроить округление».
4. Дописать комментарии-ловушки. Они и есть главная ценность словаря:
   что называется обманчиво похоже, что срабатывает вхолостую, где
   заголовок расходится с именем.
5. Заменить `$$Значение$$` на осмысленные имена переменных.
6. Перенести в `.claude/skills/<скилл>/`.

## Чего здесь нет

- **Отчётов.** Руководство описывает их много, но отчёт — не документ,
  у него другая механика (компоновка, настройки, варианты). Отдельная
  задача.
- **Справочников.** Генератор умеет их брать, но в план не включены:
  операции агента — это документы.
- **Уже готовых операций.** `НачислениеЗарплаты`,
  `НачислениеЗаПервуюПоловинуМесяца` и четыре ведомости не
  переписывались — по ним словари уже есть в `.claude/skills/`,
  и они проверены на живой форме.

## Генератор

`gen_slovar.py` + `plan.json` лежат в scratchpad сессии. Если понадобится
догенерировать — допишите документ в `plan.json` и запустите заново.
Скрипт сам находит форму: предпочитает `ФормаДокумента`, иначе
`ФормаЭлемента`, иначе `ФормаСписка`.

## Каталог метаданных

Отдельно от словарей лежит `drafts/метаданные/` — перечни имён
объектов конфигурации (документы, справочники, перечисления, регистры
накопления, начисления и удержания). Словарь отвечает «как работать
с объектом», каталог — «какие объекты есть и как называются».

## Печатные формы

Печатные формы — часть словаря документа, а не «дополнительная опция».
Заказчику нужен не рапорт «сделано», а бумаги, которые из документа
выходят: приказ, договор, записка-расчёт, справка.

Имена кнопок снимаются с формы ПРОВЕДЁННОГО документа:

```
get_form_analysis(format="buttons")   → группа ПодменюПечатьОбычное
```

Правила, общие для всех документов:

1. **Смотреть видимость.** У части форм стоит `Видимость:Нет` — они
   зависят от данных документа, периода и наличия смежных документов.
   Невидимую кнопку нажать нельзя, и это не ошибка агента.
2. **Одинаковые заголовки — разные кнопки.** У увольнения три кнопки
   «Комплект документов при увольнении» (`__1`, `__2`, `__3`), рабочая
   одна. Выбирать по видимости, а не по номеру.
3. **Сохранять только через `save_table_document_to_file`.** Кнопка
   выгрузки в файл на форме печати открывает системный диалог выбора
   папки: MCP его не водит, и он блокирует клиент тестирования целиком.
   На этом в ночь с 30 на 31.08.2026 встала работа на четыре часа.
4. **Документ по заданию из письма — печатные формы идут в ответ**,
   даже если про них не просили. Правило в `CLAUDE.md`.

Сняты с живых форм 31.08.2026: `ПриемНаРаботу`, `Увольнение`,
`КадровыйПеревод`, `Отпуск`, `ВедомостьНаВыплатуЗарплаты` (в банк).
У остальных документов подменю печати ещё не снималось — снимать
со своей формы, а не переносить по аналогии: составы разные.
