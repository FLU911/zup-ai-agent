# Каталог метаданных ЗУП КОРП 3.1

Собран 30.08.2026 с ЖИВОЙ базы «Крон-Ц» через MCP-сервер Vanessa
Automation — **без доступа к конфигуратору и без выгрузки cf**.

Зачем это отдельно от `drafts/словари/`: словари отвечают на вопрос
«как работать с объектом», а этот каталог — на вопрос «какие объекты
вообще есть и как они называются». Модель, которая угадывает имя
метаданных по заголовку формы, ошибается примерно всегда.

| Файл | Что внутри |
|---|---|
| `Документы.md` | полный список имён документов (~330) |
| `Справочники.md` | рабочий каталог справочников, сгруппированный по смыслу |
| `Перечисления.md` | перечисления НДФЛ и отчётности с именами и представлениями |
| `РегистрыНакопления.md` | 68 регистров + разбор четырёх регистров НДФЛ |
| `РегистрыСведений.md` | метод чтения любого регистра сведений, снятые составы полей, курированный список нужных |
| `НачисленияИУдержания.md` | 66 начислений и 9 удержаний с кодами дохода НДФЛ и видами дохода по взносам |

## Три приёма, которыми это снято

1. **Промах по имени.** `get_table_data` с несуществующим
   `object_name` печатает ПОЛНЫЙ список объектов этого вида:
   `object_type=1` — справочники, `2` — документы, `3` — перечисления.
   Так же ведут себя `click_button` (печатает все кнопки формы) и
   `activate_column` (печатает все колонки таблицы с заголовками).
   Промах — это не ошибка, а самый дешёвый способ разведки.

2. **Выпадающий список Универсального отчёта.** В
   `e1cib/app/Отчет.УниверсальныйОтчет` поле «Имя объекта» содержит
   полный перечень объектов выбранного вида, включая регистры и планы
   видов расчёта, до которых `get_table_data` не дотягивается.
   Подробнее — `словари/УниверсальныйОтчетКакОкноВРегистры.feature`.

3. **Список плана видов расчёта прямой ссылкой.**
   `e1cib/list/ПланВидовРасчета.Начисления` +
   `get_form_analysis(format="gherkin")` — таблица возвращается
   целиком, со всеми колонками.

## Чего здесь намеренно нет

- Полного перечня регистров сведений: их более пятисот, и подавляющее
  большинство — служебные (обмены, версии, кэши, БСП). Полный дамп
  занимает ~70 000 знаков и не помогает. Нужный регистр сведений
  проще найти через Универсальный отчёт по подстроке.
- Справочников `…ПрисоединенныеФайлы` (~350 штук) и платформенных.
- Регистров расчёта и бизнес-процессов: в задачах агента пока
  не понадобились.
