# Закрытие месяца: рабочий рецепт

Отработано вживую 28–29.08.2026: **51 месяц, октябрь 2021 — декабрь 2025,
три организации, 765 документов.** Все имена проверены на живых формах.
Один месяц = 15 документов = ~12 вызовов.

## Устройство базы Крон-Ц

Три организации, у каждой свой способ выплаты:

| Организация | Ведомость | Зарплатный проект |
|---|---|---|
| Крон-Ц | `ВедомостьНаВыплатуЗарплатыВБанк` | Сбербанк России, г. Москва №123 |
| Крон-Ц. Филиал в г. Волгоград | `ВедомостьНаВыплатуЗарплатыПеречислением` | — |
| Крон-Ц. Филиал в г. Калининград | `ВедомостьНаВыплатуЗарплатыВКассу` | — |

Имена организаций писать целиком и с `exact_match: true`.

## Даты

| Документ | Дата |
|---|---|
| Начисление за первую половину месяца | **15-е число** |
| Ведомость на аванс | 20-е число |
| Начисление зарплаты и взносов | последний день месяца |
| Ведомость на зарплату | последний день месяца |
| Отражение зарплаты в бухучете | последний день месяца |

Аванс датируется 15-м, а не 20-м. На 20-м проведение падает в те месяцы,
где 20-е — выходной: планируемая дата выплаты сдвигается назад, на
пятницу, и оказывается раньше даты документа. Ошибка выглядит так:
«Планируемая дата выплаты (19 ноября 2021 г.) не может быть меньше даты
документа (20 ноября 2021 г.)». 15-е от этого свободно.

**Декабрь — исключение по всем документам.** Январские праздники
сдвигают планируемую дату выплаты назад, внутрь декабря, и «последний
день месяца» оказывается позже неё. Замерено вживую: 2022 → 30.12,
2023 → 29.12, 2024 → 28.12, 2025 → 30.12. Правило не выводится из
календаря на глаз — читай значение с формы:

```
СоздатьДокумент → set_value Организация → input_text МесяцНачисленияСтрокой
→ simulate_tab → get_form_element_data("ПланируемаяДатаВыплаты")
```

и этой датой датируй начисление зарплаты и ведомость на зарплату.
Отражение в бухучёте про планируемую дату не знает — ему можно 31.12.

## Шаг 1. Начисление аванса (x3)

Список: `e1cib/list/Документ.НачислениеЗаПервуюПоловинуМесяца`
Создание: кнопка `ФормаСоздать`

Один документ = один вызов execute_form_actions:

```json
[{"action":"click_button","element_name":"ФормаПровестиИЗакрыть"},
 {"action":"click_button","element_name":"ФормаСоздать"},
 {"action":"set_value","element_name":"Организация","value":"<орг>","exact_match":true},
 {"action":"input_text","element_name":"МесяцНачисленияСтрокой","value":"Октябрь 2021"},
 {"action":"simulate_tab"},
 {"action":"activate_header_element","element_name":"Дата"},
 {"action":"input_text","element_name":"Дата","value":"20.10.2021"},
 {"action":"simulate_tab"},
 {"action":"click_button","element_name":"Заполнить"},
 {"action":"click_button","element_name":"ФормаПровестиИЗакрыть"}]
```

Первый документ месяца — без первого `ФормаПровестиИЗакрыть`.
Контроль заполнения — поле `ИтогНачислено`.

**Уточнение от 29.08.2026 (поймал DeepSeek на феврале 2026):** у аванса
проведение тоже может не найтись сразу после `Заполнить` —
«Элемента формы с именем <ФормаПровестиИЗакрыть> не найдено», ровно как
у начисления зарплаты. За 51 месяц на моей машине ни разу не выстрелило,
у него выстрелило на первом же документе. Видимо, зависит от скорости.
**Надёжно: у аванса тоже выносить проведение отдельным вызовом.**

## Шаг 2. Ведомости на аванс (x3)

Списки:
- `e1cib/list/Документ.ВедомостьНаВыплатуЗарплатыВБанк`
- `e1cib/list/Документ.ВедомостьНаВыплатуЗарплатыПеречислением`
- `e1cib/list/Документ.ВедомостьНаВыплатуЗарплатыВКассу`

```json
[{"action":"click_button","element_name":"ФормаСоздать"},
 {"action":"set_value","element_name":"Организация","value":"<орг>","exact_match":true},
 {"action":"input_text","element_name":"ПериодРегистрации","value":"Октябрь 2021"},
 {"action":"simulate_tab"},
 {"action":"set_value","element_name":"СпособВыплаты","value":"Аванс","exact_match":true},
 {"action":"activate_header_element","element_name":"Дата"},
 {"action":"input_text","element_name":"Дата","value":"20.10.2021"},
 {"action":"simulate_tab"},
 {"action":"click_button","element_name":"Заполнить"},
 {"action":"click_button","element_name":"ФормаПровестиИЗакрыть"}]
```

Для Крон-Ц добавить перед `Заполнить`:
`{"action":"set_value","element_name":"ЗарплатныйПроект","value":"Сбербанк России, г. Москва №123","exact_match":true}`

Поле `СпособВыплаты` называется на форме «Выплачивать».
Поле `СпособРасчетов` («учтенные как») в исторических ведомостях базы
ПУСТОЕ — заполнять не нужно, пустое значение берет все три счета.
Контроль — таблица `Состав`.

## Шаг 3. Начисление зарплаты (x3)

Список: `e1cib/list/Документ.НачислениеЗарплаты`

ЛОВУШКА: кнопка `ФормаСоздать` на этой форме НЕВИДИМА. Создание —
через `СоздатьДокумент` (первый пункт подменю «Создать»).
И она срабатывает только ПЕРВЫМ действием после `ФормаПровестиИЗакрыть`.

```json
[{"action":"click_button","element_name":"ФормаПровестиИЗакрыть"},
 {"action":"click_button","element_name":"СоздатьДокумент"},
 {"action":"set_value","element_name":"Организация","value":"<орг>","exact_match":true},
 {"action":"input_text","element_name":"МесяцНачисленияСтрокой","value":"Октябрь 2021"},
 {"action":"simulate_tab"},
 {"action":"activate_header_element","element_name":"Дата"},
 {"action":"input_text","element_name":"Дата","value":"31.10.2021"},
 {"action":"simulate_tab"},
 {"action":"click_button","element_name":"Заполнить"}]
```

ВТОРАЯ ЛОВУШКА, ТОЛЬКО НА ЭТОЙ ФОРМЕ: `ФормаПровестиИЗакрыть` в одной
цепочке с `Заполнить` периодически падает с «Элемента формы с именем
<ФормаПровестиИЗакрыть> не найдено» — расчёт зарплаты не успевает
закончиться, пока идут действия. Проведение выносить **отдельным
вызовом** `manage_form_elements`, сразу после цепочки с `Заполнить`.
Так надёжно; на остальных документах месяца этого не нужно.

## Шаг 4. Ведомости на зарплату (x3)

Так же, как ведомости на аванс (шаг 2), только `СпособВыплаты` =
«Зарплата за месяц». Список — свой под каждую организацию:

| Организация | Список |
|---|---|
| Крон-Ц | `e1cib/list/Документ.ВедомостьНаВыплатуЗарплатыВБанк` |
| Крон-Ц. Филиал в г. Волгоград | `e1cib/list/Документ.ВедомостьНаВыплатуЗарплатыПеречислением` |
| Крон-Ц. Филиал в г. Калининград | `e1cib/list/Документ.ВедомостьНаВыплатуЗарплатыВКассу` |

```json
[{"action":"click_button","element_name":"ФормаСоздать"},
 {"action":"set_value","element_name":"Организация","value":"<орг>","exact_match":true},
 {"action":"input_text","element_name":"ПериодРегистрации","value":"Октябрь 2021"},
 {"action":"simulate_tab"},
 {"action":"set_value","element_name":"СпособВыплаты","value":"Зарплата за месяц","exact_match":true},
 {"action":"set_value","element_name":"ЗарплатныйПроект","value":"Сбербанк России, г. Москва №123","exact_match":true},
 {"action":"activate_header_element","element_name":"Дата"},
 {"action":"input_text","element_name":"Дата","value":"31.10.2021"},
 {"action":"simulate_tab"},
 {"action":"click_button","element_name":"Заполнить"},
 {"action":"click_button","element_name":"ФормаПровестиИЗакрыть"}]
```

`ЗарплатныйПроект` — только у Крон-Ц, у филиалов этой строки нет.

### Почему не через «Выплатить»

На форме списка начислений есть команда «Выплатить»:

```
ФормаОбработкаСозданиеВедомостейНаВыплатуЗарплатыСоздатьВедомостиПоРасчетномуДокументу
```

Она открывает окно «Выплата начисленной зарплаты» с уже подготовленной
ведомостью — правильный тип, проект, состав, сумма. Красиво, но требует
сначала встать на нужную строку журнала, а это **и есть ловушка**:
журнал начислений отфильтрован по периоду и смешивает виды документов
с пересекающейся нумерацией. `navigate_to_row` по `Номер=0000-000004`
встал на февральское начисление зарплаты вместо ноябрьского аванса, и
это никак не проявилось до проверки запросом.

Прямое создание ведомости на 4 действия длиннее и полностью
детерминировано. 51 месяц x 3 организации прошли на нём без единого
промаха. «Выплатить» — для человека за формой, не для агента.

## Шаг 5. Отражение зарплаты в бухучете (x3)

Список: `e1cib/list/Документ.ОтражениеЗарплатыВБухучете`
Месяц — поле `ПериодРегистрации` (заголовок «Месяц»), не `МесяцНачисленияСтрокой`.

```json
[{"action":"click_button","element_name":"ФормаСоздать"},
 {"action":"set_value","element_name":"Организация","value":"<орг>","exact_match":true},
 {"action":"input_text","element_name":"ПериодРегистрации","value":"Октябрь 2021"},
 {"action":"simulate_tab"},
 {"action":"activate_header_element","element_name":"Дата"},
 {"action":"input_text","element_name":"Дата","value":"31.10.2021"},
 {"action":"simulate_tab"},
 {"action":"click_button","element_name":"Заполнить"},
 {"action":"click_button","element_name":"ФормаПровестиИЗакрыть"}]
```

НЕ вызывать `get_form_analysis` на этой форме — таблицы начислений,
НДФЛ и удержаний выводятся целиком, это тысячи строк вывода.
Контроль — `get_table_data` по документу.

## Общие наблюдения

- **Месяц вводится текстом**: «Октябрь 2021». Поля разные:
  `МесяцНачисленияСтрокой` у начислений, `ПериодРегистрации` у ведомости
  и у отражения.
- **Дата — всегда через активизацию**: `activate_header_element` →
  `input_text`. `set_value` по дате не работает.
- **`ФормаПровестиИЗакрыть` возвращает в список**, поэтому создание
  следующего документа можно цеплять в тот же вызов.
- **Проведение молчит.** Ни сообщения об успехе, ни об ошибке.
  Проверять `get_table_data`, реквизит `Проведен`.

# Ловушки, пойманные на ноябре 2021

## 1. Дата аванса — 15-е число, а не 20-е

На октябре 20-е сработало, на ноябре упало:

> Планируемая дата выплаты (19 ноября 2021 г.) не может быть меньше
> даты документа (20 ноября 2021 г.)

20.11.2021 — суббота, ЗУП сдвинул плановую выплату на пятницу 19-е,
и дата документа оказалась ПОЗЖЕ плановой выплаты.

**Правило: дата документа «Начисление за первую половину месяца» —
15-е число.** Это конец периода начисления, он всегда не позже плановой
даты выплаты, при любом расположении выходных.

Дату ведомости на аванс при этом можно оставлять 20-м: у ведомости
такого ограничения нет.

У начисления зарплаты проблемы нет: дата — последний день месяца,
плановая выплата — 5-е число следующего, всегда позже.

## 2. Начисление зарплаты: проведение — отдельным вызовом

Расчет по кнопке `Заполнить` на `НачислениеЗарплаты` идет дольше, чем
успевает отработать цепочка. Если поставить `ФормаПровестиИЗакрыть`
следующим действием в том же `execute_form_actions`, получишь

> Элемента формы с именем <ФормаПровестиИЗакрыть> не найдено

Кнопка на месте — форма просто еще не отрисовала панель. Повторный
вызов отдельным запросом проходит.

**Правило: у начисления зарплаты — два вызова. Первый до `Заполнить`
включительно, второй — проведение.** У аванса, ведомости и отражения
такого нет, там вся цепочка идет одним вызовом.

## 3. Журнал «Начисление зарплаты и взносов» — не для навигации

Форма списка `Документ.НачислениеЗарплаты` — это ЖУРНАЛ: в нем лежат
все виды начислений сразу, и номера у разных видов ПЕРЕСЕКАЮТСЯ.
`navigate_to_row` по `Номер=0000-000004` встал на февральское начисление
зарплаты вместо ноябрьского аванса.

Плюс журнал отфильтрован по периоду: отбор `Дата=15.11.2021` выдал
«Не найдено значение», хотя документ есть.

**Правило: ведомости создавать напрямую через список нужного вида
(шаг 2 и шаг 4 основного рецепта), а не через «Выплатить» из журнала.**
Прямое создание не зависит ни от фильтра списка, ни от нумерации.

Команда «Выплатить»
(`ФормаОбработкаСозданиеВедомостейНаВыплатуЗарплатыСоздатьВедомостиПоРасчетномуДокументу`)
сама по себе рабочая и удобная — она готовит ведомость нужного типа с
проектом и составом, остается дата и `Провести`. Но попасть ею в нужную
строку журнала надежно не получается. Если документ уже оплачен, она
отвечает «По документу не осталось сумм к выплате» и ничего не создает —
безопасно.

## 4. Ведомость на зарплату — то же, что на аванс

Отличие ровно одно: `СпособВыплаты` = «Зарплата за месяц» вместо
«Аванс». Дата — последний день месяца.

## Цена вопроса

Один месяц по трем организациям = 15 документов = 16-18 вызовов MCP:

| Этап | Вызовов |
|---|---|
| авансы x3 | 1 открытие списка + 2 |
| ведомости на аванс x3 | 3 открытия + 3 |
| начисления зарплаты x3 | 1 открытие + 3 создания + 3 проведения |
| ведомости на зарплату x3 | 3 открытия + 3 |
| отражения x3 | 1 открытие + 1 (все три одной цепочкой) |

## 5. Декабрь: дата начисления зарплаты — НЕ последний день месяца

Поймано 29.08.2026 на декабре 2022:

> Планируемая дата выплаты (30 декабря 2022 г.) не может быть меньше
> даты документа (31 декабря 2022 г.)

Зарплата за декабрь по настройкам выплачивается 5-го января, но январские
праздники нерабочие, и ЗУП сдвигает плановую выплату НАЗАД — на последний
рабочий день декабря. Для 2022 это 30.12. Дата документа 31.12 оказывается
позже плановой выплаты.

**Правило для декабря: прочитать поле `ПланируемаяДатаВыплаты` на форме
после ввода месяца и поставить `Дата` равной ему.** Значение зависит от
года (какой день недели выпадает на 30-31 декабря).

Ведомость на зарплату за декабрь — той же датой.
Отражение в бухучёте — можно 31 декабря, там ограничения нет.

Для всех остальных месяцев последний день месяца работает: плановая
выплата 5-го числа следующего месяца всегда позже.

### Плановые даты выплаты за декабрь, замеренные в базе

| Год | Плановая дата выплаты зарплаты за декабрь |
|---|---|
| 2022 | 30.12.2022 |
| 2023 | 29.12.2023 |

Ставить `Дата` документа начисления зарплаты и ведомости на зарплату
равной этой дате. Отражение в бухучёте — 31 декабря, там ограничения нет.
| 2024 | 28.12.2024 |

# Полное закрытие месяца: шаги 6-7 и проверка

Добавлено 29.08.2026 после января 2026. Пять шагов выше — это ещё не
весь месяц. Полный порядок:

```
аванс → ведомость аванса → начисление зарплаты → ведомость зарплаты
→ РЕЗЕРВЫ → отражение зарплаты в бухучёте → отражение удержанного НДФЛ
→ отчёты → персонифицированные сведения
```

Резервы идут ДО отражения зарплаты: у отражения есть закладка
«Выплата за счет резервов», которая берёт данные оттуда.

## Шаг 6. Резервы по оплате труда (x3)

Список: `e1cib/list/Документ.РезервыПоОплатеТруда`

Действующий документ резервов — именно этот.
`НачислениеОценочныхОбязательствПоОтпускам` — **архив**, список
открывается с заголовком «Резервы отпусков (архив)», документов там нет.

Создание — не `ФормаСоздать` (её нет), а `СоздатьРасчет`.

```json
[{"action":"click_button","element_name":"СоздатьРасчет"},
 {"action":"set_value","element_name":"Организация","value":"<орг>","exact_match":true},
 {"action":"open_choice_form","element_name":"Резерв"},
 {"action":"click_button","element_name":"ФормаВыбрать"},
 {"action":"input_text","element_name":"МесяцНачисленияСтрокой","value":"Январь 2026"},
 {"action":"simulate_tab"},
 {"action":"activate_header_element","element_name":"Дата"},
 {"action":"input_text","element_name":"Дата","value":"31.01.2026"},
 {"action":"simulate_tab"},
 {"action":"click_button","element_name":"Заполнить"}]
```
затем отдельным вызовом `ФормаПровестиИЗакрыть`.

**Поле `Резерв` не берётся `set_value`** — выпадающий список у него
всегда пуст. Только `open_choice_form` + `ФормаВыбрать`.

**Раз в год: настройка резерва.** Резерв не появится в форме выбора,
пока в `Справочник.НастройкиРасчетаРезервовПоОплатеТруда` нет элемента
на нужный год. Заводится копированием ТОЛЬКО по головной организации:

```
e1cib/list/Справочник.НастройкиРасчетаРезервовПоОплатеТруда
navigate_to_row 'Организация=Крон-Ц' → ФормаСкопировать
activate_header_element 'ГодПериода' → input_text '2026' → simulate_tab
ФормаЗаписатьИЗакрыть
```

Одно копирование создаёт настройки сразу по всем трём организациям.
На филиале — модальное «Добавлять или удалять настройки можно только
для головной организации "Крон-Ц"».

## Шаг 7. Отражение удержанного НДФЛ в бухучёте (x3)

Список: `e1cib/list/Документ.ОтражениеУдержанногоНДФЛВБухучете`
Месяц — `ПериодРегистрацииСтрокой` («Период сдачи отчетов»).
Заполнение — кнопка в таблице: `УдержанныйНДФЛЗаполнить`
(table_name `УдержанныйНДФЛ`). Форма лёгкая, всё одной цепочкой.

## Шаг 8. Проверка отчётами

| Что | Отчёт | Что смотреть |
|---|---|---|
| долг по выплатам | `АнализЗадолженностиПоЗарплате` | колонки «Долг с прошл. месяца» и «Задолженность» — пустые = нет долга |
| свод | `АнализНачисленийИУдержаний` | «Сальдо на конец месяца» |
| НДФЛ | `АнализНДФЛ` | исчислено = удержано |
| взносы | `АнализВзносовВФонды` | облагаемая база и взносы по тарифам |

Открывать `e1cib/app/Отчет.<Имя>`, период задавать явно обеими датами,
кнопка `СформироватьОтчет`, результат — элемент
**`ОтчетТабличныйДокумент`** (не «Результат»).

Читать: сохранить xlsx и разобрать `scratchpad/xlsx2txt.py`
(с `PYTHONIOENCODING=utf-8`). PDF сохраняется, но прочитать нечем.

## Шаг 9. Персонифицированные сведения (x3)

`e1cib/app/Отчет.РегламентированныйОтчетПерсонифицированныеСведенияОФизическихЛицах`
Период переключается ТОЛЬКО кнопками `УстановитьПредыдущийПериод` —
поле периода только для просмотра. Дальше `ОткрытьФормуОтчета` →
`Заполнить` → `Сохранить`. Первое «Заполнить» открывает рекламное окно
«Сдавайте отчетность прямо из программы» — закрыть и нажать ещё раз.

Подробности — `словари/ПерсонифицированныеСведенияОФизическихЛицах.feature`
и `словари/ОтчетыПроверкиМесяца.feature`.
