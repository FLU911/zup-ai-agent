Ведомость не заполнялась **не** из-за мест выплаты, регистров,
проведения или порядка документов.

Причина: `set_value` без `exact_match: true` подставлял в поле

Подробности и правило — `ЛОВУШКА-set_value-exact_match.md`.

аванс, поэтому аванс надо выплатить до расчёта зарплаты.

**Поле `Дата` капризное.** `set_value` не работает («не получилось

поле активно. `activate_header_element` сразу после `set_value` по
организации не срабатывает. Рабочая последовательность:

```
set_value Организация → input_text МесяцНачисленияСтрокой
→ simulate_tab → activate_header_element Дата → input_text Дата
→ Заполнить → ФормаПровестиИЗакрыть
```

**`ФормаПровестиИЗакрыть` возвращает в список** — значит несколько
документов создаются одной цепочкой действий без закрытия окон.

## Ведомость в банк по-прежнему не заполняется

Пересоздание начислений **не помогло**. Это уже не гипотеза, а
проверенный факт, и я исключил всё, что мог.

### Что проверено и исправно

| Звено | Состояние |
|---|---|
| Организация Крон-Ц | «В рамках зарплатного проекта», Сбербанк Москва №123 |
| Подразделение «Сектор дежурной службы» | то же (я перевёл с раздатчика) |
| Сотрудники | «Как всем», наследуют проект — проверено по карточке |
| Лицевые счета пятерых | заведены, валидные, «по лицевому счету» |
| Начисление аванса Крон-Ц январь | проведено, **59 движений** в регистре «Зарплата к выплате авансом» |
| Рязанова в начислении | есть, 14 516,13 |

### Что перепробовано и не помогло

Перепроведение · снятие с проведения и проведение заново · полное
пересоздание всех 24 документов · заполнение с отбором по проекту и
без · январь и февраль · виды выплаты «Аванс» и «Зарплата за месяц» ·
ведомость через раздатчика · дата документа 20.01.2026 и текущая ·
явная установка места выплаты сотруднику вместо «Как всем».

Везде пусто. Ошибок нет, сообщений нет.

### Что известно из исходников

Заполнение идёт так:

```
ВедомостьНаВыплатуЗарплатыФормы.ЗаполнитьНаСервере
  → МенеджерВедомости.ПараметрыЗаполненияПоОбъекту(Объект)
  → ВедомостьНаВыплатуЗарплаты.ЗарплатаКВыплате(...)
```

В `ПараметрыЗаполненияПоОбъекту` жёстко проставляется отбор:

```bsl
ПараметрыЗаполнения.ОтборСотрудников.МестоВыплаты.Вид      = ЗарплатныйПроект;
ПараметрыЗаполнения.ОтборСотрудников.МестоВыплаты.Значение = Объект.ЗарплатныйПроект;
```

Процедура `ДополнитьТаблицуЗарплатСпособамиВыплаты` строки **не
отбрасывает** — она только дополняет реквизитами зачисления. Значит
пустой приходит уже результат `ЗарплатаКВыплате`.

### Проверено дополнительно (гипотеза «важен порядок»)

Версия: начисление зарплаты за месяц зачитывает аванс, поэтому
ведомость по авансу после него не заполняется.

**Не подтвердилась.** Пометил на удаление начисление зарплаты за
январь по Крон-Ц — остался только аванс, движения зарплаты ушли.
Ведомость по авансу всё равно пуста. (Документ потом восстановлен
и проведён.)

### Долг существует — это доказано отчётом

Отчёт «Задолженность по зарплате» (`Отчет.АнализЗадолженностиПоЗарплате`),
период январь–декабрь 2026:

- **Крон-Ц: 4 780 123,41** к выплате
- филиал в Волгограде: 522 000,00
- в списке сотрудников все пятеро: Войцехович, Захаркин,
  Матвиевский, Михейцева, Рязанова

Значит данные в порядке, регистры заполнены, ЗУП долг видит.
Проблема исключительно в заполнении ведомости.

### Регистры мест выплаты проверены поштучно

| Регистр | Содержимое |
|---|---|
| `МестаВыплатыЗарплатыПодразделений` | одна запись: Крон-Ц / Сектор дежурной службы / зарплатный проект / Сбербанк Москва №123 |
| `МестаВыплатыЗарплатыСотрудников` | запись по Рязановой: зарплатный проект / Сбербанк Москва №123 |

Регистры **непериодические** — версия «запись датирована августом,
поэтому в январе её нет» отпадает.

У регистра долга `ЗарплатаКВыплатеАвансом` измерений места выплаты
**нет вообще**: сотрудник, организация, период взаиморасчетов,
подразделение, статья расходов, документ-основание. Место выплаты
подтягивается отдельным соединением.

### Отбор по месту выплаты — не причина

`ВедомостьНаВыплатуЗарплатыРасширенный.ОграничитьЗарплатыСотрудниковПоСпособуМестуВыплат`
начинается так:

```bsl
Если Зарплата.Количество() = 0 Тогда
    Возврат;
ИначеЕсли НЕ ЗначениеЗаполнено(МестоВыплаты) Тогда
    Возврат;
КонецЕсли;
```

То есть при пустом зарплатном проекте отбор по месту выплаты вообще
не выполняется. Я заполнял ведомость с пустым проектом — всё равно
пусто. **Значит таблица приходит пустой ещё раньше.**

### Где именно теряются строки

`ЗарплатаКВыплате` состоит из двух шагов, и оба под подозрением:

```
СоздатьВТСотрудникиДляВедомостиПоШапке
    ├── по документам-основаниям
    ├── по месту работы (организация + подразделение)
    └── по месту выплаты
СоздатьВТЗарплатаКВыплате
    └── ВзаиморасчетыССотрудниками, параметры:
        ПорядокВыплаты, СпособПолучения, ПериодРегистрации, Дата
```

Соединение в финальном запросе — **ВНУТРЕННЕЕ**, между
`ВТКадровыеДанныеСотрудников` и `ВТЗарплатаКВыплате`. Пустой любой
из них — пустой результат.

Отдельно подозрителен параметр **`ПорядокВыплаты`**: в словаре
`zup-payroll-accrual` он уже отмечен как источник проблем с
проведением. Если аванс зарегистрировал долг с одним порядком
выплаты, а ведомость ищет другой — внутреннее соединение даст ноль
без единого сообщения.
