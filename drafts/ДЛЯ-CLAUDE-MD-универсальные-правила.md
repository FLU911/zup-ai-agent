# Блок для вставки в CLAUDE.md, раздел «Жёсткие правила»

Править `CLAUDE.md` мне запрещено настройками проекта, поэтому блок лежит
здесь. Вставить после правила 4б, дальше перенумеровать.

Это **универсальные** ловушки — те, что бьют на любой форме и в любом
скилле. Локальные (перепутанные имена кнопок, невидимые поля конкретной
формы) остаются комментариями в своих словарях: их читают там, где жмут.

---

**4в. Ссылочные поля — только с `exact_match: true`.**
`set_value` по умолчанию ищет **по подстроке** в списке выбора. При
промахе в поле молча встаёт другой элемент справочника, а инструмент
рапортует об успехе. Проверено 28.08.2026: «Выплачивать» вместо
«Зарплата за месяц» получило «Вознаграждение сотрудникам по договорам
ГПХ», ведомость заполнилась пустой, и на поиск причины ушло полвечера.

Поля риска — те, за которыми большой справочник: `СпособВыплаты`,
`СпособРасчетов`, `ЗарплатныйПроект`, `Организация`, `Подразделение`,
`СтатьяФинансирования`, `ВидНачисления`.

Хук `PreToolUse` в `.claude/settings.json` не пропускает `set_value`
без явного `exact_match`. Если подстрочный поиск нужен осознанно —
пиши `exact_match: false`, хук пропустит. Подробности:
`drafts/ЛОВУШКА-set_value-exact_match.md`.

**4г. Врут оба исхода — и успех, и неуспех.**
Правило 4а говорит про «значение не установилось». Бывает и обратное:
на «Заявке на открытие лицевых счетов» ввод в поле `Подразделение`
пишет «не был зафиксирован выбор значения», хотя значение встало.
Проверяй `get_form_element_data` в обе стороны.

**4д. Дата документа не подставляется сама — ставь явно.**
У нового документа `Дата` остаётся текущей, и проведение падает с
«Планируемая дата выплаты не может быть меньше даты документа». В поле
`Дата` не работает `set_value` («не получилось выбрать из списка
выбора»), нужен `input_text`, и только когда поле активно. Рабочая
последовательность:

```
set_value Организация → input_text МесяцНачисленияСтрокой
→ simulate_tab → activate_header_element Дата → input_text Дата
→ Заполнить → ФормаПровестиИЗакрыть
```

`activate_header_element` сразу после `set_value` по организации не
срабатывает — отсюда `simulate_tab` перед ним.

**4е. Факт проведения проверяй запросом, а не формой.**
После «Провести» форма не меняет заголовок и не выдаёт сообщений —
успех и отказ выглядят одинаково. Смотри реквизит `Проведен` через
`get_table_data(object_type=2, ...)`.

## Заметка на будущее

Правила проекта действуют, только когда сессия запущена **из папки
`zup-ai-agent`**. При запуске из `C:\claude` файл
`zup-ai-agent/.claude/settings.json` не загружается — ни deny-лист,
ни хуки. Проверено 28.08.2026: в сессии из `C:\claude` Bash работал
свободно, хотя он в deny.

Если агент должен запускаться из другого корня — правила надо
продублировать в настройках того корня.
