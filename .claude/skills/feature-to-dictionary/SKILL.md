# Сценарий → словарь действий

В проекте два вида feature-файлов, и путать их дорого:

| | Исполняемый сценарий | Словарь действий |
|---|---|---|
| Зачем | пройти операцию от начала до конца | перечислить, что вообще можно делать |
| Теги | `@tree` | `@каталог`, `@НеЗапускать` |
| Сценариев | один, со сквозным порядком | много, каждый сам по себе |
| Кто исполняет | `run_scenario` целиком | модель сама, через MCP |

Этот скилл переводит первое во второе. Обратная операция никому не
нужна: сценарий из словаря собирает писатель (`write-autotest`).

## Зачем это нужно

Словарь из прогнанного сценария — **самый надёжный источник имён,
какой есть в проекте**. Генератор `сгенерировать-словарь.py` берёт
имена из `Form.xml`: они настоящие, но видно ли их на форме — неизвестно,
и половина оказывается скрыта функциональными опциями. А сценарий,
который прошёл зелёным, доказал каждое своё имя живой формой.

Поэтому старые сценарии не выбрасывают — их переводят.

## Как

```
python drafts/инструменты/сценарий-в-словарь.py --фича authoring/features/01_ПриемНаРаботу.feature
```

Ключи:

| Ключ | Зачем |
|---|---|
| `--фича` | исходный файл, обязателен |
| `--прогнан` | сценарий прошёл на живой базе; снимает `@черновик` и кладёт в `drafts/словари/` |
| `--вывод` | своя папка (по умолчанию `drafts/tmp/`, а с `--прогнан` — `drafts/словари/`) |
| `--имя`, `--объект` | заголовок и объект метаданных, если конвертер угадал неверно |
| `--файл` | имя файла без расширения |

**Ключ `--прогнан` ставишь не ты, а факт.** Прогонялся ли сценарий на
живой базе — смотри в `authoring/ТестПлан.MD`, колонка «Состояние».
Написано «не прогнан» — значит `--прогнан` не ставить, чего бы это ни
стоило: словарь, которому нельзя верить, хуже отсутствия словаря, потому
что читается он точно так же, как проверенный.

## Что конвертер делает сам

* выбрасывает `Попытка` и всю ветку `Исключение`;
* выбрасывает контракт результата — строки «запоминаю значение
  **выражения**» с `{"success": ...}`. Строки «запоминаю значение
  **поля**» остаются: это настоящее действие;
* выбрасывает «останавливаю выполнение сценариев», `@tree` и прочие
  теги запуска;
* каждую группу шагов `*заполним шапку` превращает в отдельный
  «Сценарий», а название переводит в неопределённую форму:
  «заполним» → «Заполнить»;
* сохраняет `Если ... Тогда` с вложенным телом, проверки `Тогда ...`,
  переменные `$$Имя$$` и комментарии автора;
* «Контекст» сценария переносит в шапку комментарием — в словаре он не
  исполняется, но помнить о нём надо;
* угадывает объект метаданных по шагу открытия формы.

## Что доделываешь ты

Конвертер честно переносит то, что было. Словарём это делает работа
после него:

1. **Полнота.** Сценарий покрывал одну операцию, словарь описывает
   объект целиком. Открой форму и посмотри `get_form_analysis`: чего
   в словаре нет — кнопок печати, закладок, команд списка. Дописать.
2. **Названия сценариев.** Конвертер переводит первый глагол по
   короткому списку; всё, что он не знал, осталось как было. Название
   должно отвечать на вопрос «что я могу сделать», а не «что делал тест».
3. **Комментарии-ловушки.** Самое ценное в словарях проекта — строки
   вида «на новом документе это поле скрыто» и «кнопка врёт, смотри
   таблицу». Из сценария они не переносятся, потому что там их нет.
   Всё, что знаешь про эту форму, дописать комментариями.
4. **Шапка.** Заголовки окон формы и списка, дата и версия ЗУП, на
   которой имена сняты.
5. **Порядок.** В словаре сценарии стоят в порядке «сначала открыть,
   потом заполнить, потом провести», а не в порядке теста.

## Куда класть результат

| Состояние | Куда |
|---|---|
| источник прогнан или имена сверены с формой | `drafts/словари/`, либо рядом со скиллом операции |
| источник не прогнан | `drafts/tmp/`, и только туда |

**Черновик в `drafts/словари/` не кладут.** Правило заведено 01.09.2026,
когда оттуда удалили шесть неподтверждённых словарей: модель берёт имена
только из словаря и отличить черновик от проверенного не может.
Подробности — `docs/09-покрытие-и-проверка-словарей.md`.

Сверить словарь с живой формой и снять `@черновик`:

```
python drafts/инструменты/сверить-словарь.py --словарь <файл> --живые <имена.txt> \
    --что "Документ.X, форма нового документа" --заметка "что выяснилось"
```

## Проверить, что получилось

1. `check_syntax` через MCP — словарь остаётся валидным Gherkin,
   даже если его никогда не запускают.
2. Глазами: нет ли осевшего контракта результата
   (`grep "значение выражения"` должен молчать), стоят ли
   `@каталог` и `@НеЗапускать`.
3. `@НеЗапускать` — не украшение. Словарь, запущенный через
   `run_scenario`, закроет все окна клиента и пойдёт выполнять действия
   вперемешку.
