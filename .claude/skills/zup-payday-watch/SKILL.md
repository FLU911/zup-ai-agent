# Расчётный день

Третий канал постановки задач после чата и почты — календарь. Никто
ничего не просит: наступает 20-е число, и аванс должен быть начислен
и выплачен. Скилл описывает ОДИН проход по календарю.

## Один тик

Полный регламент — `календарь/ЦИКЛ-расчетный-день.md`. Читай его
целиком перед работой, здесь только каркас:

1. Подключить клиент тестирования.
2. Взять дни выплат из `календарь/настройки.json` и **сверить с базой**
   (регистр `НастройкиЗарплатаКадрыРасширенная`). Разошлись — стоп,
   вопрос человеку.
3. Понять, что сегодня за день: аванс, зарплата, ничего. День выпал на
   выходной — работать в предшествующий рабочий день, перенос только назад.
4. Проверить `календарь/состояние.json` И саму базу: не сделано ли уже.
5. День аванса: начисление за первую половину месяца (дата — 15-е) →
   ведомость на аванс (дата — 20-е), по каждой организации.
6. День зарплаты: начисление зарплаты → ведомость → резервы → отражение
   зарплаты в бухучёте → отражение удержанного НДФЛ, по каждой организации.
7. Проверить отчётами, обновить `календарь/состояние.json` и `календарь/журнал.md`, доложить.

Обычный день — тик заканчивается на шаге 3 молча.

## Три правила, которые важнее расписания

**Аванс — до расчёта зарплаты за тот же месяц.** Начисление зарплаты
зачитывает аванс. Наоборот — ведомость по авансу заполнится пустой,
и ни одной ошибки при этом не будет.

**Дни выплат не выдумывать.** Они лежат в настройках организаций и
в `настройки.json`. Расхождение между ними — повод спросить человека,
а не выбрать то, что кажется разумнее, и тем более не поправить базу.

**Месяцы раньше `не-раньше-месяца` не трогать.** В этой базе май —
август 2026 специально оставлены пустыми под задания другим моделям.
Цикл, который решит их «догнать», испортит эксперимент.

## Что легко забыть

* **Проведение молчит.** Ни сообщения об успехе, ни об ошибке.
  Проверять `get_table_data`, реквизит `Проведен`.
* **У начисления зарплаты проведение — отдельным вызовом.** Расчёт по
  кнопке `Заполнить` идёт дольше, чем успевает отработать цепочка,
  и `ФормаПровестиИЗакрыть` в том же вызове падает с «Элемента формы
  не найдено». У аванса это тоже случается — выносить тоже.
* **Дата документа аванса — 15-е, а не 20-е.** В месяцы, где 20-е
  выпадает на выходной, ЗУП сдвигает плановую выплату назад, и дата
  документа оказывается позже неё: документ не проводится.
* **Декабрь — исключение по всем документам.** Плановая дата выплаты
  уезжает внутрь декабря из-за январских праздников. Читать
  `ПланируемаяДатаВыплаты` с формы и датировать по ней.
* **Расчёт при увольнении в общую ведомость не входит.** Ему отдельная
  ведомость по документу увольнения.

Имена элементов, готовые цепочки действий и все ловушки —
`drafts/РЕЦЕПТ-закрытие-месяца-по-шагам.md`; порядок этапов месяца —
скилл `zup-month-close`; сами документы — `zup-advance-accrual`,
`zup-payroll-accrual`, `zup-payout`.

## Постоянное наблюдение

Один тик — это один день. Чтобы агент смотрел в календарь сам,
в Claude Code есть повторяющаяся задача:

```
/loop 12h /zup-payday-watch
```

Раз в двенадцать часов, а не раз в сутки, намеренно: так расчётный день
не проскочит, если один тик пришёлся на неудачный момент. В обычный день
тик заканчивается молча и почти мгновенно.

В OpenCode `/loop` нет — там ту же работу делает скрипт, вызывающий
`opencode run` в цикле:

```powershell
календарь\следить-за-календарем.ps1 -Цикл расчет -Инструмент opencode
```

```bash
календарь/следить-за-календарем.sh расчет opencode
```

И `/loop`, и скрипт живут, пока открыта сессия или терминал. Пропущенный
день цикл догонит сам — при условии, что месяц не раньше границы
`не-раньше-месяца`.
