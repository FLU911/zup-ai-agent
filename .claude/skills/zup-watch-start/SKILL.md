# Завести регламент

Календарь и почта — каналы заданий, по которым никто ничего не просит.
Чтобы агент смотрел в них сам, в сессии должны тикать таймеры. Таймеры
живут в памяти программы, а не на диске: **новая сессия начинается
с пустого списка**, и заводить их надо заново. Этот скилл делает это
одним вызовом.

Что именно заводить — `регламент/задания.json`. Список один на оба
инструмента; сюда его не переписывай, читай файл.

## Порядок

1. Прочитать `регламент/задания.json`.
2. `CronList` — что уже заведено в этой сессии. Задание, чей текст
   совпадает с `/<скилл>` из списка, второй раз **не заводить**.
3. Для каждого недостающего — `CronCreate`:
   `cron` — из поля `cron` как есть, `prompt` — `/<скилл>`,
   `recurring: true`.
4. Задания с `"сразу": true` выполнить один раз тут же, по очереди, не
   дожидаясь таймера: сессию могли открыть как раз в день аванса.
   Обычный день — тик заканчивается молча, это нормально.
5. Доложить человеку таблицей: задание, расписание, номер таймера.
   И одной строкой — до какого числа это проработает (см. ниже).

## Три вещи, о которых надо сказать человеку

**Срок — семь дней.** Повторяющаяся задача в Claude Code сама удаляется
через неделю. Назови дату, когда регламент надо завести снова.

**Только пока открыта сессия.** Закрыл окно, перезагрузился — таймеров
нет. Продолжение старой сессии (`--continue`) возвращает переписку,
но не таймеры: в истории будет написано «завёл», а тикать ничего не
будет. Поэтому после любого перезапуска — снова `CronList`, а не вера
переписке.

**Одна сессия на базу.** Два окна с заведённым регламентом — это два
агента, которые в один день пойдут начислять один и тот же аванс.
От задвоения документов страхуют `календарь/состояние.json` и проверка
по базе внутри самих скиллов, но два клиента в одних формах мешают друг
другу. Второе окно открыто для другой работы — регламент в нём
не заводить.

## Показать и остановить

Показать — `CronList`. Остановить одно — `CronDelete` по номеру.
Остановить всё — `CronDelete` по каждому заданию из списка; чужие
таймеры, которых в `задания.json` нет, не трогать.

## Чего этот скилл не делает

Он не решает, какой сегодня день, и ничего не начисляет. Таймер знает
только имя скилла; что сегодня — аванс, зарплата, срок отчёта или
ничего — решает сам скилл на каждом тике: `zup-payday-watch`,
`zup-reporting-watch`, `zup-mail-watch`.

## Без открытой сессии

Тот же список снаружи обходит скрипт — он годится и для OpenCode, где
таймеров в сессии нет вообще:

```powershell
регламент\следить.ps1                        # claude
регламент\следить.ps1 -Инструмент opencode
регламент\следить.ps1 -Показать              # что и как часто, без запуска
```

Скрипт живёт, пока открыт терминал, зато не знает недельного срока.
