# Написание тестов многоагентной цепочкой

Проект умеет не только выполнять операции, но и писать новые — сам.
Это перенос многоагентного пайплайна из
[документации Vanessa Automation](https://pr-mex.github.io/vanessa-automation/dev/AI/)
на субагентов Claude Code.

## Зачем цепочка, а не один агент

Один агент, который «пойдёт и напишет автотест», делает две вещи плохо:
уходит в интерфейс, не разобравшись с данными, и объявляет сценарий готовым,
потому что тот один раз отработал. Цепочка разводит это по ролям, и каждая
роль умеет только своё.

| Субагент | Что делает | Чего не делает |
|---|---|---|
| `va-data-analyst` | собирает командный интерфейс и данные из базы | ничего не меняет в базе |
| `va-researcher` | проходит сценарий руками в UI, пишет запись действий | не создаёт вспомогательные тестовые данные |
| `va-reviewer-research` | проверяет исследование по чек-листу | не правит исследование |
| `va-code-analyst` | ищет в исходниках причину UI-блокировки | не трогает UI |
| `va-writer` | пишет feature-файл и отлаживает прогонами | не считает работу готовой без реального запуска |
| `va-reviewer-feature` | machine-check через grep и `check_syntax` + чек-лист | не правит feature |
| `va-db-admin` | восстанавливает базу из DT между сценариями | не завершает процессы 1С |

## Цепочка на один сценарий

```
Шаг 0   va-data-analyst        → authoring/data/АнализДанных_<NN>_<Имя>.MD
Шаг 1   va-researcher          → authoring/research/РезультатИсследования_<NN>_<Имя>.MD
Шаг 2б  проверка данных        → есть ли блокер «нет тестовых данных»
Шаг 2   va-reviewer-research   → authoring/rewiew/..._Researcher_<N>.MD
Шаг 3а  va-code-analyst        → только при маркере UI_CONFIG_BLOCK
Шаг 3   va-writer              → authoring/features/<NN>_<Имя>.feature
Шаг 4   va-reviewer-feature    → authoring/rewiew/..._Writer_<N>.MD
Шаг 5   Gate Check             → и только потом «✅ Готово»
Шаг 5б  va-db-admin            → authoring/restore/Restore_<NN>_<Имя>.MD
```

Полный протокол со всеми лимитами итераций и правилами обработки ошибок —
`authoring/ПодготовкаУправляющегоАгента.MD`. Это оригинал из репозитория
Vanessa Automation, он здесь главный.

## Gate Check

Сценарий получает статус «✅ Готово» только если:

1. существует файл ревью исследования;
2. существует файл ревью feature-файла;
3. **оба** содержат вердикт `✅ КОРРЕКТЕН`.

Ноль ошибок в `get_test_results` сам по себе ничего не значит. Это защита от
самой частой поломки многоагентных пайплайнов: после успешного шага агент
склонен «сэкономить» и пропустить проверку.

## Как запустить

1. Опишите сценарий в `authoring/ТестПлан.MD` в форме **Дано / Когда / Тогда**.
   Свободная форма, но заголовок обязателен: `## Тест <NN>: <КраткоеНазвание>`.
2. Проверьте `authoring/ПараметрыКонфигурации.MD` — все девять параметров.
3. Скажите агенту:

   ```
   Напиши автотест по сценарию 01 из ТестПлана
   ```

Агент загрузит скилл `write-autotest` и поведёт цепочку, отчитываясь после
каждого шага.

## Дополнительное требование этого проекта

В обычном проекте покрытия тестами сценарий пишется для регресса.
Здесь каждый сценарий потом становится **операцией боевого агента**, поэтому
к нему предъявляется требование сверх `InstructionsWriteScenario.md`:
у каждого этапа должен быть признак успеха, проверяемый по форме или
по базе, а не рапорт самого сценария. См. [архитектуру](02-архитектура.md).

Эталон оформления — `.claude/skills/zup-6ndfl-report/6-НДФЛ.feature`.

## Ограничение текущего стенда

Шаг 5б (восстановление базы из DT) сейчас не работает: менеджер тестирования
и клиент тестирования используют одну файловую базу, а DT-эталон не выгружен.
Пока это так, `va-db-admin` не запускается, и сценарии обязаны убирать за собой
сами. Подробности и способ починить — `authoring/ПараметрыКонфигурации.MD`,
раздел «Ограничения текущего стенда».

## Про ограничение инструментов субагентов

Субагенты наследуют все инструменты сессии — перечислять 38 MCP-инструментов
в поле `tools` каждого агента непрактично. Ограничения задаются двумя другими
способами:

- `.claude/settings.json` — permissions уровня проекта (`allow` / `ask` / `deny`);
- текст промпта каждого субагента — там подробные запреты, унаследованные
  из шаблонов Vanessa (не завершать процессы 1С, не создавать тестовые данные,
  не выходить за каталог проекта).

Если нужен более жёсткий контроль — перечислите конкретные инструменты
в frontmatter агента полем `tools`.
