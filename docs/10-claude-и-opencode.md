# Claude Code и OpenCode: один проект, два инструмента

Проект должен одинаково работать из обоих. Claude Code — основной,
OpenCode — то, чем к базе подключаются другие модели (DeepSeek, Qwen,
YandexGPT) для сравнения. Если инструменты настроены по-разному,
сравнение моделей превращается в сравнение конфигураций.

Здесь — что откуда берётся и что проверять после правки настроек.

## Где что лежит

| Что | Claude Code | OpenCode |
|---|---|---|
| сервер MCP | `.mcp.json` | блок `mcp` в `opencode.jsonc` |
| правила проекта | `CLAUDE.md` (читается сам) | `instructions` в `opencode.jsonc` |
| скиллы | `.claude/skills/**/SKILL.md` | **те же файлы**, OpenCode читает их сам |
| команды с косой чертой | имя скилла: `/zup-payout` | `.opencode/command/*.md` |
| субагенты | `.claude/agents/*.md` | блок `agent` в `opencode.jsonc`, промпт — `{file:...}` из тех же файлов |
| разрешения | `permissions` в `.claude/settings.json` | блок `permission` в `opencode.jsonc` |
| запрет на set_value без exact_match | хук `.claude/hooks/check_exact_match.py` | плагин `.opencode/plugin/exact-match.js` |

Единственный текст, существующий в двух копиях, — проверка exact_match:
на питоне для Claude Code, на JS для OpenCode. Правишь одну — правь
вторую, в обоих файлах об этом написано. Чтобы копии не разъезжались
молча, есть сверка:

```
python drafts/инструменты/сверить-хук-exact-match.py
```

Она прогоняет обе через девять одинаковых случаев и возвращает 1, если
хотя бы на одном решения разошлись. Запускать после каждой правки любой
из копий.

## Три места, где легко разъехаться

**1. Таймаут MCP.** У OpenCode по умолчанию **5 секунд**. Расчёт зарплаты
по кнопке «Заполнить» идёт до получаса, ведомость по трём организациям —
минуты. Без явного `timeout` в блоке `mcp` модель получает обрыв вызова
и начинает «чинить» то, что на самом деле успешно считается. В
`opencode.jsonc` стоит 2 400 000 мс — столько же, сколько в `.mcp.json`
у Claude Code.

**2. Имена инструментов MCP.** У Claude Code это `mcp__VA__run_scenario`,
у OpenCode — `va_run_scenario`: имя сервера плюс подчёркивание. Один и
тот же инструмент, два написания. В разрешениях это разные строки.

**3. Разрешения не наследуются.** У Claude Code запрет живёт в
`.claude/settings.json`, и OpenCode про этот файл ничего не знает.
Блок `permission` в `opencode.jsonc` — ручное зеркало, и его надо
править вместе с оригиналом. Что там сейчас:

| Действие | Оба инструмента |
|---|---|
| чтение базы и репозитория | без вопросов |
| изменение данных (`execute_form_actions`, `execute_feature_step`) | спрашивает |
| правка файлов | спрашивает, кроме `.claude/skills/**` и `CLAUDE.md` — там запрет |
| запись действий пользователя, правка командного интерфейса | запрет |
| bash, веб | запрет |

## Как проверить, что инструменты согласованы

```bash
opencode run --dir . "перечисли инструменты, которые начинаются на va_, и скажи, сколько их"
```

Сервер отдаёт 37 инструментов — столько же должно быть видно и здесь.
Разрешения список не укорачивают: запрещённый инструмент виден, но
вызвать его нельзя. Проверять надо именно вызовом — попросить
`va_user_actions_recording`, он обязан не пройти.

```bash
opencode run --dir . "какие скиллы тебе доступны?"
```

Должны найтись все каталоги из `.claude/skills/`.

Проверка плагина: попросить сделать `set_value` без `exact_match` —
вызов обязан не пройти с объяснением про подстрочный поиск.

## Чего в OpenCode нет

* **Хуков в том виде, в каком они есть у Claude Code.** Есть плагины на
  JS с событиями `tool.execute.before` и `tool.execute.after` — этого
  хватает для запретов, но не для всего.
* **Чтения `.claude/agents/`.** Скиллы OpenCode берёт из `.claude/`,
  субагентов — нет, поэтому они перечислены в `opencode.jsonc`.
  Описание субагента там приходится держать копией.
* **`.claude/settings.local.json`** — локальные разрешения конкретной
  машины мимо OpenCode тоже проходят.

## Модели

Какая модель тянет вождение форм 1С, а какая нет — отдельный вопрос,
он в `drafts/ДЛЯ-ДРУГИХ-ИИ/00-КАК-ПОЛЬЗОВАТЬСЯ.md` и в отчётах прогонов.
Коротко: контекст меньше 100k на MCP-сервере с 37 инструментами
не живёт — модель умирает через несколько вызовов.
