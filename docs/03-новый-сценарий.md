# Как добавить свою операцию

Одна бизнес-операция = один скилл + один feature-файл.

```
.claude/skills/<имя-скилла>/
├── SKILL.md          ← что спросить у человека и в каком порядке запускать
└── <Операция>.feature ← шаги в интерфейсе 1С
```

## 1. Запишите сценарий руками

Не пишите feature-файл с нуля — запишите действия и потом почистите.

В Vanessa Automation есть запись действий пользователя (`user_actions_recording`
в MCP, кнопка записи в интерфейсе). Пройдите операцию как обычный пользователь,
остановите запись, экспортируйте в Turbo Gherkin.

Получится «болванка» — сырой список шагов. Пример такой болванки лежит в
`features/`. Её нельзя отдавать агенту как есть: там нет проверок, нет
переменных и нет признаков успеха.

## 2. Вынесите изменяемое в переменные

Всё, что человек назовёт при постановке задачи — организация, период, дата,
путь — заменяется на `$$ИмяПеременной$$`:

```gherkin
И из выпадающего списка с именем 'Организация' я выбираю по строке "$$ПеременнаяНаименованиеОрганизации$$"
```

Именуйте переменные одинаково во всех сценариях. Разнобой
(`ПеремОрганизация` в одном файле, `ПеременнаяНаименованиеОрганизации` в
другом) — самый частый источник поломок.

## 3. Разбейте на этапы и оберните каждый

Этап — это осмысленный кусок операции, про который есть что сказать человеку:
«отчёт заполнен», «документ проведён», «контрольные соотношения сошлись».

```gherkin
*заполним отчет
    Попытка
        И я нажимаю на кнопку с именем 'Заполнить'
        Тогда открылась форма с именем 'ОбщаяФорма.ДлительнаяОперация'
        И я жду закрытия формы с именем "ОбщаяФорма.ДлительнаяОперация" в течение 1800 секунд
        И Я запоминаю значение выражения '{"success":true,"result":"мы заполнили отчет данными"}' в переменную "РезультатВыполненияАгентомШага5"
    Исключение
        И Я запоминаю значение выражения '{"success":false,"result":"возникла ошибка при заполнении отчета"}' в переменную "РезультатВыполненияАгентомШага5"
        Затем я останавливаю выполнение сценариев данной фичи
```

Правила:

- номер переменной = порядковый номер этапа, без пропусков;
- в `Исключение` обязательно `Затем я останавливаю выполнение сценариев данной фичи` —
  иначе сценарий поедет дальше по сломанной форме;
- текст в `result` пишите **для человека**, а не для лога. Это ровно то, что
  агент покажет пользователю;
- добавляйте явное ожидание (`я жду закрытия формы ... в течение N секунд`)
  везде, где 1С показывает «Длительная операция». Расчёт зарплаты и заполнение
  отчётности легко уходят за десять минут.

## 4. Проверьте синтаксис до запуска

```
mcp__VA__open_feature_file(filePath="<полный путь>/<Операция>.feature")
mcp__VA__check_syntax(filePath="<полный путь>/<Операция>.feature")
```

Открыть файл перед проверкой обязательно: на неоткрытом файле `check_syntax`
падает с внутренней ошибкой (см. [известные проблемы](04-известные-проблемы.md)).

Инструмент найдёт неизвестные шаги и структурные ошибки. Полезно и просто
как проверка, что вы не выдумали шаг, которого в Vanessa нет.

Найти нужный шаг:

```
mcp__VA__search_for_steps_by_keywords(...)
```

## 5. Напишите SKILL.md

Frontmatter обязателен:

```markdown
---
name: zup-hire-employee
description: Оформляет приём сотрудника на работу в 1С:ЗУП через Vanessa Automation. Используй, когда просят принять, оформить или трудоустроить сотрудника.
---
```

`description` — это то, по чему агент решает, брать скилл или нет. Пишите там
слова, которыми пользователь реально сформулирует задачу.

Дальше в теле — таблица входных переменных, таблица этапов, порядок вызовов
и ограничения. Возьмите за образец `.claude/skills/zup-6ndfl-report/SKILL.md`.

## 6. Прогоните и посмотрите на формулировки

Запустите операцию от лица человека, который не читал ваш сценарий.
Если из ответа агента непонятно, что произошло в базе — правьте тексты
`result`, а не промпт.

## Чек-лист перед сдачей сценария

- [ ] Все изменяемые значения вынесены в `$$переменные$$`
- [ ] Имена переменных совпадают с другими сценариями проекта
- [ ] Каждый этап в `Попытка / Исключение`
- [ ] В каждом `Исключение` есть остановка фичи
- [ ] Номера `РезультатВыполненияАгентомШагаN` идут подряд
- [ ] Тексты `result` понятны человеку без контекста
- [ ] Есть ожидания для длительных операций
- [ ] `check_syntax` не находит ошибок
- [ ] Файл сохранён в UTF-8 **with BOM**
- [ ] В `SKILL.md` описаны все входные переменные и ограничения
