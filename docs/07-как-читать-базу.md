# Как читать базу 1С через MCP

Собрано 30.08.2026 после ночи, потраченной на поиск расхождения в 6-НДФЛ.
Смысл документа простой: **почти всё время уходит не на то, чтобы что-то
сделать в базе, а на то, чтобы понять, что в ней есть.** Ниже — все
способы чтения, найденные за проект, от самого дешёвого к самому
трудоёмкому. Выбирать надо сверху вниз.

Правила из `CLAUDE.md` действуют: имена элементов брать из словарей,
проверять, что значение установилось, отсутствие ответа MCP ошибкой
не считать.

---

## 1. Прямой запрос к данным — `get_table_data`

Самое дешёвое. Работает для справочников, документов, перечислений
и констант.

```
get_table_data(object_type=2, object_name="ВедомостьНаВыплатуЗарплатыВБанк",
               date_start="01.01.2026 00:00:00", date_end="31.03.2026 23:59:59",
               limit=40)
```

Возвращает дату, номер, признаки проведения и пометки удаления и —
главное — **навигационную ссылку** на каждый объект. Ссылка потом
открывает документ одним вызовом.

`object_type`: 1 справочник, 2 документ, 3 перечисление, 4 одна
константа, 5 все константы, 6 реквизиты по навигационной ссылке.

**Существование документа проверять только так**, а не по форме списка:
отбор на форме может молча не установиться, и список окажется пустым
при живых документах.

## 2. Промах по имени — бесплатный каталог метаданных

Если передать несуществующее `object_name`, инструмент печатает
**полный перечень объектов этого вида**. Это не ошибка, а разведка.

Так же ведут себя:
- `click_button` с несуществующей кнопкой — печатает все кнопки формы;
- `activate_column` с несуществующей колонкой — печатает все колонки
  таблицы вместе с заголовками;
- `switch_tab` с несуществующей группой — печатает все закладки формы;
- `set_value` в поле выбора — печатает содержимое выпадающего списка.

Не угадывать имена. Заголовок и имя метаданных расходятся регулярно:
«Операция учета НДФЛ» — это `ОперацияНалоговогоУчетаПоНДФЛ`.

Снятые каталоги лежат в `drafts/метаданные/` — сначала смотреть туда.

## 3. Реквизиты открытого объекта — `get_object_attributes`

Работает только на форме объекта (не списка, не отчёта).

```
get_object_attributes(data_mode="all", only_filled=true)
get_object_attributes(data_mode="single_attribute", attribute_name="ДатаПолученияДохода")
get_object_attributes(data_mode="single_tabular_section", tabular_section_name="НДФЛ")
```

Показывает **реквизиты, которых нет на форме**. Табличная часть «НДФЛ»
ведомости именно так и нашлась — на форме её не видно вовсе.

Осторожно с размером: ТЧ «НДФЛ» ведомости на 120 строк — это 140 000
знаков. Ответ уедет в файл, и его придётся разбирать `grep`.

## 4. Состояние формы — `get_form_analysis`

| Формат | Что даёт |
|---|---|
| `gherkin` | значения всех полей и содержимое таблиц целиком |
| `elements` | дерево элементов с флагами видимости |
| `buttons` | только кнопки |
| `messages` | окно сообщений пользователю |

`gherkin` на форме списка справочника или плана видов расчёта возвращает
всю таблицу — так снят полный список начислений с кодами дохода НДФЛ.

**Но на списке регистра накопления это вешает MCP-сервер на 120 секунд**
и заодно все соседние вызовы. Для регистров — следующий пункт.

## 5. Универсальный отчёт — окно в любой регистр

`e1cib/app/Отчет.УниверсальныйОтчет`

Читает **любой регистр построчно, со всей аналитикой**. Единственный
найденный способ увидеть пересечение измерений — расшифровка отчёта
даёт разрез по людям, стандартные отчёты по датам, а нужно бывает
и то и другое разом.

```
Тип объекта  = Регистр накопления
Имя объекта  = Расчеты налогоплательщиков с бюджетом по НДФЛ
Имя таблицы  = Остатки и обороты
период       = 01.01.2026 – 31.03.2026
click_button 'СформироватьОтчет'
save_table_document_to_file('ОтчетТабличныйДокумент', format='xlsx')
```

Ловушки, рецепт и разложение колонок —
`drafts/словари/УниверсальныйОтчетКакОкноВРегистры.feature`.

Выпадающий список «Имя объекта» — заодно полный перечень объектов
выбранного вида, включая регистры и планы видов расчёта, до которых
`get_table_data` не дотягивается.

## 5а. Командный интерфейс — где что лежит в программе

`manage_command_interface` отвечает на вопрос «а как эта команда
называется и где она в меню».

```
action="get_section_panel"                  → 17 разделов
action="click_section_panel", command="Кадры", returnFunctionPanel=true
```

Возвращает все команды раздела, разбитые по группам, и **у каждой —
навигационную ссылку** вида `e1cib/command/Документ.<Имя>.ОткрытьСписок`
или `e1cib/command/Обработка.<Имя>.Открыть`. Это единственный найденный
способ добраться до обработок и журналов документов, у которых нет
привычной ссылки `e1cib/list/…`.

**Осторожно:** без `returnFunctionPanel: true` панель функций остаётся
открытой и БЛОКИРУЕТ интерфейс клиента тестирования, пока из неё не
выберут команду. С флагом панель закрывается сама. Если всё-таки
заблокировали — `action="close_function_panel"`.

Разделы: Главное, Подбор персонала, Мотивация, Обучение и развитие,
Кадры, Зарплата, Выплаты, Налоги и взносы, Отчетность справки,
Охрана труда, Настройка, Администрирование, Самообслуживание,
Откат изменений данных, MCP, Помощь.

## 6. Готовые отчёты конфигурации

`e1cib/app/Отчет.<Имя>`, результат — `ОтчетТабличныйДокумент`.

| Вопрос | Отчёт |
|---|---|
| есть ли долг по выплатам | `АнализЗадолженностиПоЗарплате` |
| свод по зарплате за месяц | `АнализНачисленийИУдержаний` |
| НДФЛ исчислен / удержан | `АнализНДФЛ`, `АнализНДФЛДетальный` |
| взносы | `АнализВзносовВФонды` |
| резервы | `ОстаткиИОборотыРезервовПоОплатеТруда` |

Период по умолчанию берётся откуда угодно (у одного отчёта «этот год»,
у другого июль 2013) — задавать обе даты явно через
`activate_header_element` + `input_text` + `simulate_tab`.

## 7. Расшифровка строки регламентированного отчёта

Ячейки листов **именованные**. Имена достаются из самого отчёта:
сохранить лист в `mxl` и вытащить строки в кавычках. В 6-НДФЛ имя
строится как `П0000200` + номер строки + `03`.

Порядок важен именно такой:
1. сценарием VA встать на нужный раздел и на ячейку;
2. **дать сценарию завершиться**;
3. отдельным вызовом `manage_form_elements` нажать `Расшифровать`.

Нажатие `Расшифровать` внутри сценария вешает весь MCP-сервер.

## 8. Выгрузка табличного документа и разбор питоном

```
save_table_document_to_file(file_name="...xlsx",
                            form_element_name="ОтчетТабличныйДокумент",
                            format="xlsx")
python drafts/инструменты/xlsx2tsv.py файл.xlsx > файл.tsv
```

**Только `xlsx2tsv.py`.** Старый `xlsx2txt.py` выбрасывает пустые ячейки,
колонки съезжают, и разбор по индексу даёт правдоподобный неверный
ответ — худший вид ошибки. См. `04-известные-проблемы.md`.

Под Windows всегда `PYTHONIOENCODING=utf-8`.

Формат `pdf` тоже поддерживается, но прочитать его нечем.

## Порядок действий, когда цифра в отчёте не сходится

Проверено на разборе КС 1.14, где три сессии ушли на перебор гипотез,
а ответ дал один правильно заданный запрос.

1. **Записать саму формулу нарушения** и все её слагаемые. Проверка
   контрольных соотношений печатает и формулу, и значения строк —
   выгрузить это окно в xlsx, а не пересказывать.
2. **Найти регистр**, из которого берётся каждое слагаемое. Слагаемые
   одной формулы могут приходить из РАЗНЫХ регистров и отбираться по
   РАЗНЫМ полям — именно на этом всё и ломается.
3. **Выгрузить регистр Универсальным отчётом** за период отчёта
   и посчитать слагаемое самому. Сошлось — модель верна, не сошлось —
   гипотеза о регистре неверна, возвращаться к пункту 2.
4. **Найти строки-исключения**: те, что попадают в одно слагаемое и не
   попадают в другое. Их сумма и есть расхождение. Если она в точности
   равна разрыву — причина найдена.
5. **Найти документ-регистратор** этих строк и чинить ЕГО, а не отчёт.
   Правка регистров «Переносом данных» и добивка операциями учёта —
   это лечение следствия; оно почти всегда переносит расхождение
   в соседнюю строку.

Одно правило важнее остальных: **не подбирать**. Каждая проверенная
гипотеза должна либо подтверждаться числом, сошедшимся до рубля,
либо отбрасываться.
