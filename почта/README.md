# Почта как канал заданий

Второй способ поставить агенту задачу, кроме чата: человек пишет письмо
на ящик агента, агент выполняет задание в базе и отвечает — с расчётами,
номерами документов и печатными формами во вложении.

```
почта/
  ЦИКЛ-мониторинг-почты.md   регламент одного тика: что делать по шагам
  настройки.example.json     образец настроек — скопировать в настройки.json
  обработанные.json          состояние: какие письма уже разобраны
  журнал.md                  человеческая запись о каждом разобранном письме
  следить-за-почтой.ps1      наблюдатель для Windows
  следить-за-почтой.sh       он же для bash
```

## Что нужно в базе

Подсистема «Взаимодействия» из БСП с настроенной учётной записью
электронной почты: документы `ЭлектронноеПисьмоВходящее` и
`ЭлектронноеПисьмоИсходящее`, приём по IMAP, отправка по SMTP.
Пароль от ящика живёт в самой 1С, в репозиторий не выносится.

## Настройка

```bash
cp почта/настройки.example.json почта/настройки.json
```

и вписать свои адреса:

```json
{
  "учетная-запись-агента": "agent@example.com",
  "белый-список-отправителей": ["customer@example.com"],
  "тема-задания": "Задание",
  "интервал-проверки-секунд": 60
}
```

`настройки.json` закрыт в `.gitignore` — реальные адреса в репозиторий
не попадают.

**Белый список — это граница безопасности, а не удобство.** Агент
отвечает только на перечисленные адреса, совпадение точное. Письмо
с любого другого адреса помечается `не-задание` и остаётся без ответа,
даже если задание в нём написано и выглядит разумным: отправка письма
наружу от имени организации необратима, и решение об этом принимает
человек.

## Как запустить наблюдение

Одним тиком, вручную:

```
Claude Code:  /zup-mail-watch
OpenCode:     /почта
```

Постоянно, скриптом (одинаково работает с обоими инструментами):

```powershell
почта\следить-за-почтой.ps1                          # claude, интервал из настроек
почта\следить-за-почтой.ps1 -Инструмент opencode
почта\следить-за-почтой.ps1 -Один                    # один тик и выход
```

```bash
почта/следить-за-почтой.sh                 # claude
почта/следить-за-почтой.sh opencode 300    # opencode, раз в 5 минут
ODIN_TIK=1 почта/следить-за-почтой.sh      # один тик и выход
```

Внутри сессии Claude Code то же самое делает повторяющаяся задача:

```
/loop 1m Выполни один тик почтового цикла по регламенту почта/ЦИКЛ-мониторинг-почты.md. Новых писем нет — молчи.
```

Скрипт живёт, пока открыт терминал; `/loop` — пока открыта сессия.
Нужно наблюдение, которое переживёт перезагрузку, — ставьте скрипт
в планировщик задач Windows или в cron.

## Три вещи, на которых спотыкаются все

1. **Новые письма сами в базе не появятся.** Их приносит команда
   «Отправить и получить» в журнале «Взаимодействия», и она же
   отправляет всё, что стоит в очереди.
2. **Кнопка «Отправить» на форме письма ничего не отправляет.** Она
   ставит письмо в очередь, окно закрывается, и это выглядит как успех.
   Доказательство отправки — реквизиты исходящего: `СтатусПисьма`
   = «Отправлено», заполнена `ДатаОтправления`, выдан
   `ИдентификаторСообщения`.
3. **Создан кадровый документ — к ответу идут его печатные формы.**
   Заказчику нужны приказ и договор, а не сообщение «сделано».

Остальные ловушки — в `ЦИКЛ-мониторинг-почты.md` и в словаре
