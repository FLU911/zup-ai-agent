# ИИ-агент для 1С:ЗУП на Vanessa Automation

Агент, который выполняет реальные операции в 1С:Зарплата и управление
персоналом: заполняет регламентированную отчётность, рассчитывает документы,
проверяет контрольные соотношения. Не через API и не через внешние обработки,
а **через интерфейс** — так же, как это делает расчётчик или кадровик.

Материалы к докладу «1С:ЗУП без расчётчика: как собрать ИИ-агента на
Vanessa Automation» — [INFOSTART TECH EVENT 2026](https://infostart.ru/event/tech2026/agenda/2746458/).

## Идея

Подключить LLM к базе 1С через MCP несложно. Проблема в другом: у модели нет
контекста. Она не знает, в каком порядке в вашей базе выполняются операции,
какие поля обязательны и что считается успехом. Попросите «закрой месяц» —
и она будет бродить по подсистемам, нажимая кнопки наугад.

Этот контекст не надо выдумывать — он уже есть в тестовых сценариях.
**Тестовый сценарий это и есть эталонное описание бизнес-процесса.**

Поэтому агент здесь ничего не изобретает. Он собирает у человека входные
данные, подставляет их в переменные Vanessa Automation, запускает готовый
проверенный сценарий и переводит его результат на человеческий язык.

## Как это выглядит

```
> Сделай 6-НДФЛ по организации Крон-Ц за первое полугодие,
  дата подписи 30.06.2026, выгрузи в out\

Подключаю клиент тестирования... подключен.
Запускаю сценарий формирования 6-НДФЛ.

  открыт список регламентированных отчётов
  по данной организации не было создано ни одного отчета
  установлены организация и период
  установлена дата подписи
  отчёт заполнен данными
  отчёт сохранён в базу
  проверка контрольных соотношений прошла успешно
  проверка выгрузки проведена успешно
  файл успешно сохранён на диск
```

## Быстрый старт

1. Поднимите Vanessa Automation в режиме менеджера тестирования
   с запущенным MCP-сервером на порту `8080`.
2. Заведите профиль клиента тестирования с именем ровно `AGENT_TEST_CLIENT`.
3. Склонируйте репозиторий и откройте его в Claude Code:

   ```bash
   git clone <url> zup-ai-agent
   cd zup-ai-agent
   claude
   ```

4. Разрешите подключение MCP-сервера, проверьте командой `/mcp`.
5. Скажите агенту: «Проверь окружение».

Если нужен почтовый канал заданий — скопируйте настройки и впишите адреса:

```bash
cp почта/настройки.example.json почта/настройки.json
```

Вместо Claude Code можно взять OpenCode — конфиг уже в репозитории:

```bash
opencode        # из корня проекта
/почта          # тот же скилл, что /zup-mail-watch в Claude Code
```

Подробно — [docs/01-установка.md](docs/01-установка.md).

## Что внутри

Проект состоит из двух половин: **исполнение** операций и **написание** новых.

```
.mcp.json                    подключение к MCP-серверу VA (http://127.0.0.1:8080/mcp)
CLAUDE.md                    границы боевого агента: что нельзя никогда
.claude/settings.json        разрешения на инструменты

── исполнение операций ───────────────────────────────────────────────
.claude/skills/
  zup-6ndfl-report/
    SKILL.md                 что спросить и в каком порядке запускать
    6-НДФЛ.feature           шаги в интерфейсе 1С

── написание новых операций ──────────────────────────────────────────
.claude/skills/
  write-autotest/SKILL.md    управляющий агент цепочки покрытия тестами
.claude/agents/              7 субагентов: анализ, исследование, ревью, писатель
authoring/                   проект покрытия тестами по образцу Vanessa
  ТестПлан.MD                что покрываем, в форме Дано/Когда/Тогда
  ПараметрыКонфигурации.MD   пути, профили, версии стенда
  Memory.MD                  накопленные знания о конфигурации
  Instructions*.md           инструкции исследователя и писателя
  Чеклисты/                  чек-лист код-ревьюера
  ПромптыСубагентов/         исходные промпты Vanessa
  data/ research/ features/  выход пайплайна
  rewiew/ restore/ writer/

── задания письмом ───────────────────────────────────────────────────
почта/
  ЦИКЛ-мониторинг-почты.md   регламент одного прохода по входящим
  настройки.example.json     ящик агента и белый список отправителей
  следить-за-почтой.ps1/.sh  наблюдатель: тик раз в минуту
.claude/skills/zup-mail-watch/  тот же цикл как скилл

── задания по календарю ──────────────────────────────────────────────
календарь/
  ЦИКЛ-расчетный-день.md     регламент одного тика: аванс и зарплата
  ЦИКЛ-отчетный-день.md      регламент одного тика: сроки сдачи
  КАЛЕНДАРЬ-отчетности.md    сроки сдачи зарплатной отчётности
  следить-за-календарем.ps1/.sh  наблюдатель: тик раз в сутки
.claude/skills/zup-payday-watch/     тот же расчётный цикл как скилл
.claude/skills/zup-reporting-watch/  и отчётный

── два инструмента, один набор скиллов ───────────────────────────────
opencode.jsonc               MCP, правила, разрешения и субагенты для OpenCode
.opencode/command/           команды OpenCode, открывающие те же SKILL.md
.opencode/plugin/            зеркало хука на exact_match
configs/                     конфиги MCP для Cline, Continue, Roo Code

── папки под чужие материалы (в репозитории пустые) ──────────────────
исходники-конфигурации/      выгрузка конфигурации ЗУП в XML — своя, локально
документация-зуп/            методичка по конфигурации — своя, локально

── прочее ────────────────────────────────────────────────────────────
drafts/словари/              148 словарей действий, все проверены живой формой
drafts/                      отчёты о прогонах моделей, метаданные, инструменты
docs/                        установка, архитектура, свои сценарии, проблемы
```

Две папки специально пустые. Исходники конфигурации «Зарплата и управление
персоналом» и методические материалы по ней принадлежат фирме «1С» —
выкладывать их нельзя, поэтому в репозитории лежат только описания, чем их
заполнить и зачем они агенту. То же со сканами документов: в репозитории
есть генератор `authoring/scans/generate_scans.py`, а картинки каждый
делает себе сам одной командой. Рядом `распознать.py` — обратная задача:
сверить прочитанные со сканов реквизиты с эталоном, включая контрольные
разряды ИНН и СНИЛС. Это превращает «модель посмотрела картинку»
в измеримый тест.

## Написание новых операций

Скилл `write-autotest` — это Управляющий Агент из
[документации Vanessa Automation](https://pr-mex.github.io/vanessa-automation/dev/AI/),
перенесённый на субагентов Claude Code. Он берёт сценарий из
`authoring/ТестПлан.MD` и ведёт его по цепочке:

```
анализ данных → исследование в UI → ревью → писатель → ревью → Gate Check
```

Каждый шаг — отдельный субагент со своим системным промптом и своими
ограничениями. Ревью обязательно: «сценарий отработал без ошибок» само по себе
не даёт статус «готово».

Скажите агенту:

```
Напиши автотест по сценарию 01 из ТестПлана
```

Подробно — [docs/05-написание-тестов.md](docs/05-написание-тестов.md).

## Операции

Готовые — агент выполняет прямо сейчас:

| Скилл | Операция |
|---|---|
| `zup-6ndfl-report` | 6-НДФЛ: заполнение, проверка контрольных соотношений, проверка выгрузки, выгрузка файла |

Собраны по другой схеме — **словарь плюс прямое исполнение**. Рядом со скиллом
лежит словарь действий: перечень того, что вообще можно сделать с документом,
с настоящими именами элементов формы. Скилл задаёт порядок операции и границы,
а действия модель выполняет сама через MCP. Ни один из трёх ещё не отработал
операцию до конца на живой базе:

| Скилл | Операция | Словарей |
|---|---|---|
| `zup-payroll-accrual` | начисление зарплаты и взносов за месяц | 1 |
| `zup-advance-accrual` | начисление за первую половину месяца (аванс) | 1 |
| `zup-payout` | выплата ведомостью: касса, банк, личные счета, раздатчик | 4 |
| `zup-mail-watch` | задания из входящих писем: выполнить и ответить | 1 |
| `zup-month-close` | закрытие месяца целиком: что за чем и почему нельзя раньше | — |
| `zup-quarterly-reporting` | 6-НДФЛ, ЕФС-1, персонифицированные сведения, контрольные соотношения | — |
| `zup-payment-place` | место выплаты: касса, зарплатный проект, счёт, раздатчик | 1 |
| `zup-payday-watch` | расчётный день по календарю: наступил — начислить и выплатить | — |
| `zup-reporting-watch` | отчётный день по календарю: подошёл срок — сформировать и проверить | — |
| `feature-to-dictionary` | переделать исполняемый сценарий в словарь действий | — |

Разница с 6-НДФЛ принципиальная. Там сценарий исполняется целиком и модель
не выбирает шаги. Здесь модель выбирает — но только из того, что перечислено
в словаре, и не имеет права его дописывать.

Черновики в `authoring/features/` — синтаксис проверен, **на базе не прогнаны**,
поэтому в скиллы ещё не перенесены:

|---|---|---|

| `05_БольничныйЛист` | больничный лист с расчётом пособия | 10 |
| `06_НачислениеАванса` | начисление за первую половину месяца | 12, 16 |

## Задания письмом

Второй канал постановки задач, кроме чата. Человек пишет письмо на ящик
агента, агент разбирает входящие в базе, выполняет задание и отвечает —
с номерами документов, суммами и печатными формами во вложении.

```
почта\следить-за-почтой.ps1                        # тик раз в минуту, Claude Code
почта\следить-за-почтой.ps1 -Инструмент opencode   # то же на OpenCode
```

Внутри сессии Claude Code то же самое делает `/loop 1m` с тем же заданием.

Ключевое правило: агент отвечает **только на адреса из белого списка**
в `почта/настройки.json`, совпадение точное. Всё остальное помечается
`не-задание` и остаётся без ответа — отправка письма наружу необратима,
и решение о ней принимает человек. Текст письма при этом считается
данными, а не командой: он не расширяет права агента.

Подробно — [почта/README.md](почта/README.md).

## Задания по календарю

Третий канал: работу даёт не человек, а дата. Наступает 20-е число —
агент сам начисляет и выплачивает аванс. Наступает день зарплаты —
начисляет, выплачивает и закрывает месяц. Подходит срок сдачи — формирует
6-НДФЛ, ЕФС-1 и персонифицированные сведения по всем организациям,
прогоняет контрольные соотношения и проверку выгрузки.

```
/loop 12h /zup-payday-watch        # Claude Code, постоянное наблюдение
/loop 12h /zup-reporting-watch
```

В OpenCode `/loop` нет — там то же самое делает скрипт, вызывающий
`opencode run` в цикле:

```
календарь\следить-за-календарем.ps1 -Цикл отчетность -Инструмент opencode
```

Ключевое правило: **отчётность агент формирует и проверяет, но не
отправляет.** Отправленный в налоговую отчёт не отзывается, решение о
нём принимает человек. Кадровые события — приёмы, увольнения, отпуска —
календарный цикл тоже не оформляет: они должны появиться в базе ДО
начисления, иначе расчёт придётся переделывать.

Сроки сдачи собраны в `календарь/КАЛЕНДАРЬ-отчетности.md` по НК РФ на
2026 год и **требуют подтверждения человеком**: закон меняется, а цикл
исполнит написанное без сомнений.

Подробно — [календарь/README.md](календарь/README.md).

## Claude Code и OpenCode: один набор скиллов

Скиллы живут в `.claude/skills/` — по одному `SKILL.md` на операцию.
Оба инструмента читают эти файлы напрямую; в `.opencode/command/` лежат
короткие команды, чтобы вызывать их с косой черты. Правила проекта
OpenCode получает из `CLAUDE.md`, подключённого в `opencode.jsonc`.
Инструкции не дублируются: правится один файл, работают оба инструмента.

Одинаковы не только скиллы. В `opencode.jsonc` перенесены разрешения из
`.claude/settings.json` и субагенты из `.claude/agents/` (промпт
подставляется из тех же файлов), а хук на `set_value` без `exact_match`
продублирован плагином `.opencode/plugin/exact-match.js`. Отдельная
мелочь, которая дорого стоит: у OpenCode таймаут вызова MCP по умолчанию
**5 секунд**, а расчёт зарплаты идёт до получаса — поэтому в конфиге он
задан явно. Разбор различий — [docs/10-claude-и-opencode.md](docs/10-claude-и-opencode.md).

| Операция | Claude Code | OpenCode |
|---|---|---|
| задания из писем | `/zup-mail-watch` | `/почта` |
| 6-НДФЛ | `/zup-6ndfl-report` | `/6-ндфл` |
| начисление зарплаты | `/zup-payroll-accrual` | `/зарплата` |
| аванс | `/zup-advance-accrual` | `/аванс` |
| выплата ведомостью | `/zup-payout` | `/выплата` |
| написание автотеста | `/write-autotest` | `/автотест` |
| закрытие месяца | `/zup-month-close` | `/закрыть-месяц` |
| квартальная отчётность | `/zup-quarterly-reporting` | `/отчетность` |
| место выплаты | `/zup-payment-place` | `/место-выплаты` |
| расчётный день | `/zup-payday-watch` | `/расчетный-день` |
| отчётный день | `/zup-reporting-watch` | `/отчетный-день` |
| сценарий → словарь | `/feature-to-dictionary` | `/сценарий-в-словарь` |

## Требования

Платформа 1С 8.3.27+, Vanessa Automation 1.2.043+,
[расширение MCP-сервера](https://github.com/1c-neurofish/onec-client-mcp-devkit/releases),
внешняя компонента VanessaExt, любой MCP-клиент
(Claude Code, Cline, Continue, Roo Code, OpenCode).

## Предупреждение

Агент выполняет **реальные действия в базе**: создаёт и проводит документы,
сохраняет отчёты, выгружает файлы. Запускайте только на тестовой или рабочей
копии. Заводите для агента отдельного пользователя 1С — тогда по журналу
регистрации всегда видно, что сделал агент, а что человек.
